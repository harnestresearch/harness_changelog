## Highlights

- **Raised Node.js Requirement to `^24.22.3 || >=26.13.1` for November 2026 `undici` Security Fixes** _(Source-Verified for Official Note)_: Raises the declared Node.js engine range from `>=24.9.0` to `^24.22.3 || >=26.13.1` in root `package.json` and `@deepseek-ai/dsh` (`apps/cli/package.json`), aligning system Node installations with the first Node 24 (`24.22.3`, bundling `undici 7.30.2`) and Node 26 (`26.13.1`, bundling `undici 8.12.4`) security releases.
  - **Exact Allowed vs. Excluded Node.js Versions**: Allows **`24.x >= 24.22.3`** (not limited to exact `24.22.3`) and **`>= 26.13.1`** (including `26.13.1+` and unbounded `27+` under semver, though CI only tests `24.22.3`, latest `24.x`, and floating `26`). Rejects **`< 24.22.3`** (Node 20/22/23 and `24.0.0`–`24.22.2`), **all `25.x`** (excluded by the `^24.22.3` `<25.0.0-0` upper bound), and **`26.0.0`–`26.13.0`**.
  - **Where Checked vs. Not Checked**: Declared in package manifests (`engines.node`) without `engine-strict=true` in the repository; **DSH CLI startup has no runtime `process.versions.node` blocker**, and the Python SDK dev-only `DSH_RUNTIME_MODE=node` launcher only updates its missing-`node` error hint without running `node --version`. Strict equality (`=== '24.22.3'`) applies only to the CI build-backed compatibility gate (`DSH_NODE_COMPAT_BUILD=1`) and bundled primary-runtime / Python single-file executable packaging.
- **Aligned Bundled Runtimes, Electron `^44.11.5`, `undici` Overrides & Vendor Alpha Bumps** _(Source-Verified, Unlisted in Official Notes)_: Upgrades workspace `undici` overrides and direct dependencies (`6.29.1` / `7.30.2` / `8.12.4`), bumps Desktop Electron from `^44.7.0` to `^44.11.5` (embedding Node `24.22.3`) with `node-addon-require-builtin` `^0.1.10`, pins `24.22.3` in the Desktop/SDK primary runtime lockfile and Python SDK single-file executable builder, and bumps 9 internal Cordis/Cosmokit/Schemastery vendor packages to `*-alpha.1`. **No user-facing UI, CLI, protocol, tool, or plugin features changed compared with `0.2.3-alpha.1`.**

## Official Release Notes vs. Source-Verified Changes

### Official Release Notes (`dsh-v0.2.3-alpha.2`)

- *"DSH now requires Node.js 24.22.3 or later in the 24.x series, or 26.13.1 or later. by @imccyu"* (`调整 Node.js 版本要求为 24.22.3，26.13.1 及以上版本。 @imccyu`)

### Source-Verified Semver Semantics & Scope Boundaries (`dsh-v0.2.3-alpha.1..dsh-v0.2.3-alpha.2`)

- **Chinese vs. English Release Note Precision**: The Chinese release note wording (`24.22.3，26.13.1 及以上版本`) can be misread as pinning `24.22.3` strictly or allowing `25.x`/`26.x`. Source `engines.node` (`^24.22.3 || >=26.13.1`, matching the English wording) allows `>=24.22.3 <25.0.0-0` and `>=26.13.1`:
  - `24.x`: `24.22.3` and any newer `24.x` (`>=24.22.3`, not `==24.22.3`); `24.0.0`–`24.22.2` are no longer supported.
  - `25.x`: **Not matched** by `^24.22.3 || >=26.13.1` (previously technically admitted by `>=24.9.0`).
  - `26.x`: `26.0.0`–`26.13.0` are excluded; `26.13.1` and newer `26.x` are allowed.
  - `27.x+`: **Allowed by semver** (`>=26.13.1` has no upper major cap), but **untested in CI** (CI `node-compat` runs pinned `24.22.3` and floating `26` only).
- **Affected vs. Unaffected Distributions**:
  - **Affected (must upgrade host Node.js)**: npm `@deepseek-ai/dsh` installations, source checkouts, CI/container environments, and the Python SDK's explicit dev-only `DSH_RUNTIME_MODE=node` carrier.
  - **Unaffected (self-contained Node `24.22.3`)**: Packaged `@deepseek-ai/dsh-desktop` applications (via Electron `^44.11.5` and bundled primary runtime `nodeVersion: 24.22.3`) and the Python SDK's bundled single-file executable (now pinned to `node24.22.3-<platform>-<arch>`).
  - **Unchanged Independent Addon**: `@deepseek-ai/node-addon-system*` retains `engines.node: ">=20"`.
- **No Functional Runtime Changes Outside Runtime Floor & Dependencies**: Under `packages/*/*/src`, only 3 source comments were updated (`app-boot`, `hmr`, `ptc-runtime-node`); legacy Node `<24.12` v1 ESM loader adapters remain in source (marked unreachable on supported runtimes).

## Breaking Changes & Migration

- **Minimum Node.js Version Bump (`docs/upgrade-guide/v0.2.3-alpha.1/node-24-22-3/guide.{md,zh.md}`)**:
  - Adds `1` bilingual upgrade guide (stored under directory `v0.2.3-alpha.1/` though first shipped in `dsh-v0.2.3-alpha.2`).
  - Users running DSH via npm, source checkout, or `DSH_RUNTIME_MODE=node` on Node `<24.22.3`, `25.x`, or `26.0.0`–`26.13.0` should upgrade host Node.js to **`24.22.3+` (24.x)** or **`26.13.1+`**, verify with `node --version`, and rerun `pnpm install` for source checkouts.
  - No config, profile, Session v4 JSONL, or plugin API migrations are required over `0.2.3-alpha.1`.
