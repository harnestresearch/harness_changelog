## Highlights

- **Route-Based Automatic Web Search Default & Settings UI Rename** _(Source-Verified for Official Note: "DeepSeek models use DeepSeek server-side search with no per-search charge; other models default to DeepSeek Search API")_: Shipped base compositions no longer pin `web.searchProvider: deepseek-search-api`. Under the new **Automatic** default in **Plugins → Official → Web search and fetch**, unconfigured `web_search` calls on the built-in `deepseek-official` and `deepseek-account` LLM provider routes use **DeepSeek server-side search** (`deepseek-official`, renamed across all 8 UI languages from **DeepSeek (legacy)**), while all other model routes and non-model searches use **DeepSeek Search API** (`deepseek-search-api`); `web_fetch` remains on local `http`.
- **Inline Snippet Extraction in DeepSeek Server-Side Search** _(Source-Verified, Unlisted in Official Notes)_: `@deepseek-ai/dsh-web-search-deepseek` now preserves inline `snippet` fields directly from `web_search_result` items before falling back to `text`-block `citations[].cited_text`, ensuring server-side search returns page excerpts even when the Anthropic-compatible `/anthropic/v1/messages` endpoint omits text-block `citations`.

## Official Release Notes vs. Source-Verified Changes

### Official Release Notes (`dsh-v0.2.2-rc.5`)

- *"DeepSeek models use DeepSeek server-side search with no per-search charge; other models default to DeepSeek Search API. by @LegGasai"* (`DeepSeek 模型使用 DeepSeek 服务端搜索，搜索不按次收费；其他模型默认使用 DeepSeek Search API。 @LegGasai`)

### Source-Verified Routing, Fallback, Migration & Billing Boundaries (`dsh-v0.2.2-rc.4..dsh-v0.2.2-rc.5`)

- **Routing Boundary (Provider Route IDs, Not Model Names, PR #8707)**:
  - `WebRuntime` (`@deepseek-ai/dsh-web`) matches `WebSearchRequest.llmProvider` (populated by `@deepseek-ai/dsh-tool-web` from `session.requestContext()?.provider` and matched in `searchReady(modelSelection.provider)`) against the fixed two-route set `{'deepseek-official', 'deepseek-account'}`—**not** the model name string.
  - Consequently, DeepSeek models called through custom OpenAI/Anthropic-compatible provider profiles (`@deepseek-ai/dsh-llm-pi-ai` or other route IDs), as well as programmatic `ctx.web.search()` calls outside a model request (`llmProvider === undefined`), still default to `deepseek-search-api`.
- **Fallback Conditions (Local `available()` Fallthrough Only; Zero Execution Fallback)**:
  - **Configured Provider**: An explicit `web.searchProvider` or `$DSH_WEB_SEARCH_PROVIDER` applies to every route with no fallback (`WEB_PROVIDER_CONFIGURED_MISSING` or `WEB_PROVIDER_CONFIGURED_UNAVAILABLE`).
  - **Unconfigured (`Automatic`)**: Prefers `deepseek-official` on `deepseek-official` / `deepseek-account` routes and `deepseek-search-api` otherwise when registered and locally `available()`. Only if the preferred provider is unregistered or locally `available() === false` does `resolveProvider()` fall through to a single remaining usable provider (throwing `WEB_PROVIDER_AMBIGUOUS` if multiple others are usable, or `WEB_PROVIDER_UNAVAILABLE` if none are).
  - **No Runtime / Network Fallback**: Once selected, HTTP/auth/endpoint failures (`WEB_PROVIDER_ERROR`, `WEB_PROVIDER_CREDENTIAL_MISSING`, `WEB_ABORTED`) fail immediately and **never** switch to the other search provider.
- **Billing Claim Boundaries (Not "Free Search"; Unverified Against Live Invoices)**:
  - **Token vs. Per-Request Cost**: Official copy waives only the **per-search API call charge** on `deepseek-official` server-side search—each distinct query still dispatches an auxiliary Anthropic-compatible Messages turn (`deepseek-v4-flash`, `max_tokens: 4096`, up to `maxUses: 5`) that **consumes extra model tokens** (*"No per-search charge, but every search uses extra model tokens"*), whereas `deepseek-search-api` (used on other routes or when pinned) incurs per-request Search API charges under `searchBilling`.
  - **Source Proof Limit**: Source code only governs client-side endpoint routing and UI strings; actual server-side billing/metering depends on the remote DeepSeek backend or gateway and was **not** verified at runtime.

## Breaking Changes & Migration

- **Default Search Backend Shift & Custom Gateway Endpoint Mismatch (`docs/upgrade-guide/v0.2.2-rc.4/web-search-deepseek-model-default`)**:
  - Unconfigured conversations on `deepseek-official` / `deepseek-account` switch from `/v1/tools/search` to auxiliary `/anthropic/v1/messages` calls (now appending `web/deepseek-search-llm-request` session events).
  - **Gateway Deployments**: Unlike `deepseek-search-api`, `web-search-deepseek` does **not** inherit the chat model provider's `baseURL`; it sends `web-search-deepseek.apiKeyEnv` (`DEEPSEEK_API_KEY` by default) to `web-search-deepseek.baseURL` → `$DEEPSEEK_SEARCH_BASE_URL` → `https://api.deepseek.com/anthropic/v1`. Deployments pointing `deepseek-official` at a custom gateway will fail `web_search` until they set `web-search-deepseek.baseURL` / `$DEEPSEEK_SEARCH_BASE_URL` or pin **DeepSeek Search API** (`searchProvider: deepseek-search-api`).
  - **Stored Config & Persistence Compatibility**: Existing stored `web.searchProvider` selections, `$DSH_WEB_SEARCH_PROVIDER`, `fetchProvider: http`, and Session v4 JSONL logs remain compatible without rewrite.
