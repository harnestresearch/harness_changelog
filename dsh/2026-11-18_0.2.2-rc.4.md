## Highlights

- **Dedicated `CONTENT_REFUSED` Handling & Billed Usage Accounting on DeepSeek Stream Refusals** _(Source-Verified for Official Note: "Improve handling of unexpected model responses")_: When a DeepSeek Messages stream ends with `stop_reason: "refusal"`, `@deepseek-ai/dsh-llm-deepseek` now records billed pre-refusal token usage and fails the turn with the new non-retryable `CONTENT_REFUSED` error code (preserving provider `stop_details.explanation`, such as blocked image indices) instead of throwing `MALFORMED_RESPONSE` mid-delta and dropping usage; the Web UI withdraws any partially streamed draft while keeping it in `assistant/attempt` outside model history.
- **Desktop LiveShare Tunnel Worker `ELECTRON_RUN_AS_NODE` Fix** _(Source-Verified for Official Note: "Fix LiveShare failing to create shares in the desktop app")_: Fixed `@deepseek-ai/dsh-experimental-liveshare` on the `mac` / `win` Electron Desktop app spawning its owner-gateway child process (`process.execPath`) without forwarding `ELECTRON_RUN_AS_NODE`, which previously caused the worker to launch as a second GUI app instance and immediately exit under the Desktop single-instance lock before any share could register.

## Official Release Notes vs. Source-Verified Changes

### Official Release Notes (`dsh-v0.2.2-rc.4`)

- *"Improve handling of unexpected model responses. by @turtle2099"* (`优化模型请求收到异常消息响应时的表现。 @turtle2099`)
- *"Fix LiveShare failing to create shares in the desktop app. by @mektpoy"* (`修复 LiveShare 在桌面端无法创建分享的问题。 @mektpoy`)

### Source-Verified Mechanisms & Scope (`dsh-v0.2.2-rc.3..dsh-v0.2.2-rc.4`)

- **Streamed DeepSeek Content-Safety Refusal Classification (`@deepseek-ai/dsh-llm-deepseek` & `@deepseek-ai/dsh-llm`, PR #8584)**:
  - **Narrow Scope**: Despite the broad official wording (*"unexpected model responses"*), the code change applies specifically to DeepSeek Messages SSE streams ending with `delta.stop_reason === "refusal"`. Genuine protocol errors still raise `MALFORMED_RESPONSE` or `STREAM_CLOSED`, empty terminal stops still raise `EMPTY_RESPONSE`, pre-stream input rejections still fail as HTTP `400` `INVALID_REQUEST`, outgoing request payloads remain unchanged (no `safety_check` request field is sent), and other LLM adapters are untouched.
  - **Behavior**: Yields final `usage` (`inputTokens`, `outputTokens`, cache tokens, and `totalTokens`) on `message_stop` before throwing `LlmError(..., "CONTENT_REFUSED")` with `"DeepSeek refused to answer under its content safety review"` (plus `: <explanation>` when `stop_details.explanation` is provided). Unlike `MALFORMED_RESPONSE`, `CONTENT_REFUSED` is excluded from retry-policy choices so normal retry policies end the attempt immediately.
- **Desktop Electron Node-Mode Forwarding for LiveShare Gateway Worker (`@deepseek-ai/dsh-experimental-liveshare`, PR #8634)**:
  - `TunnelWorker.start()` now forwards `ELECTRON_RUN_AS_NODE` from the Host environment (`workerNodeModeEnv(process.env)`) when spawning `process.execPath` for the owner-gateway worker. Under `@deepseek-ai/dsh-desktop` (`mac` / `win`), this runs `owner-gateway/cli.js` in Electron's Node mode instead of triggering a second GUI startup terminated (`exit code 0`) by `requestSingleInstanceLock()`, while leaving standalone Node CLI/Web Hosts (`ubuntu` / `mac` / `win` without `ELECTRON_RUN_AS_NODE`) unchanged.
- **LiveShare Owner Credential Horizon Test Clock Fix (PR #8638, Unlisted in Official Notes)**:
  - Updated `owner-credential-horizon.host.spec.ts` to compute past/live credential horizons relative to `Date.now()` instead of a hardcoded `2026-10-15` + 30-day (`2026-11-14`) timestamp (test-only; no runtime behavior change).

## Breaking Changes

- **SDK / Event Error-Code Change (`CONTENT_REFUSED`, `docs/upgrade-guide/v0.2.2-rc.3/deepseek-refusal-code`)**:
  - Code or integrations classifying LLM error finishes or failed `turn/end` errors for streamed DeepSeek `stop_reason: "refusal"` now receive `CONTENT_REFUSED` instead of `MALFORMED_RESPONSE` and should route `CONTENT_REFUSED` to a provider-refusal user message.
  - **No End-User Config or Session Persistence Break**: Existing Session v4 JSONL files, `cordis.yml` profiles, CLI flags, and Desktop installations upgrade in place from `0.2.2-rc.3`.
