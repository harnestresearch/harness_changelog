## Highlights (Statically Observed in macOS `arm64` Package)

- **Renderer Subscription Cap Drain-and-Recheck (`ApplicationTransport.subscribe`)**: In renderer transport chunk `BHeyMntc.js`, hitting the existing `64`-subscription limit no longer throws `APPLICATION_RATE_LIMITED` immediately—it now awaits in-flight `releaseRequested` subscriptions (`waitForReleases`) and re-checks capacity before rejecting (retaining the `64` cap rather than removing it), and adds a 30-second-throttled `warn` log (`"Application subscription limit reached"`, per-method `active`/`establishing`/`releasing`/`releaseFailed`/`oldestAgeMs`). Connecting this code change to the official fix for *"tasks failing to open after frequent task switching or notification backlogs"* is a static behavioral inference without live runtime verification.
- **Worker Runtime Prompt & Telemetry Copy for Bash Risk / Auto Approval (`14,169 → 14,175`, `+6`)**: Decoded `qoder-worker-runtime.obf.mjs` string entries add six strings (`+6 / −0`): an approval-evaluation instruction (`"Previous assistant replies are prior approval verdicts, not user authorization… Evaluate only the latest action against all retained user instructions…"`), a Bash risk self-assessment prompt covering nested shells, and four telemetry/field descriptions (`Bash risk input`, `First local Auto gate reason`, `First matching Auto blacklist rule identifier`, and `Local Auto approval policy version`). These additions verify prompt and description text changes only and do **not** by themselves prove that a new approval policy is active or enforced.
- **Agent SDK `1.0.60-alpha.62`, `qodercli` `1.1.86-hotfix.5.2` & `xlsx-sidecar` Rebuild**: Advances `@qoder-ai/qoder-agent-sdk` / `@qoder-ai/qoder-cn-agent-sdk` from `1.0.60-alpha.50` to `1.0.60-alpha.62`, updates `qoderCliVersion` and its on-demand OSS download template from `1.1.86-hotfix.5` to `1.1.86-hotfix.5.2` on Electron `43.8.4`, and repackages `qoder-office-xlsx` with a recompiled Rust `xlsx-sidecar`.
