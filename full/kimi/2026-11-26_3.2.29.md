## Overview & Comparison Boundaries

This entry analyzes the **`3.2.28 → 3.2.29`** desktop release pair using official versioned macOS `arm64` and Windows `x64` packages (four installers total; each download's MD5 matched the CDN `ETag` captured via `HEAD`, verifying transport integrity only). Intermediate desktop releases between `3.2.25` and `3.2.29` are not all cataloged or analyzed in this repository (`3.2.28` has no entry yet, and `3.2.26`/`3.2.27` remain Windows-only `TODO` placeholders), so `3.2.25` is **not** the comparison baseline.

## Unannounced Major Subsystem: Local File Version History (`restic`-Backed)

**Not mentioned in the official `3.2.29` changelog**, the largest technical addition in `3.2.29` is a complete local file version history subsystem present on both macOS `arm64` and Windows `x64`:

- **IPC Surface (`0 → 13` Channels)**: `3.2.28` contains `0` `kimi-agent:file-history-*` channels. `3.2.29` introduces **`13` distinct channels** confirmed in decoded main-process bundles and `out/preload/ipc-channels-*.mjs` on both macOS and Windows:
  - `kimi-agent:file-history-list`
  - `kimi-agent:file-history-read-version`
  - `kimi-agent:file-history-image`
  - `kimi-agent:file-history-image-cancel`
  - `kimi-agent:file-history-diff`
  - `kimi-agent:file-history-summary`
  - `kimi-agent:file-history-restore`
  - `kimi-agent:file-history-status`
  - `kimi-agent:file-history-changed`
  - `kimi-agent:file-history-attach`
  - `kimi-agent:file-history-edit-sessions-ack`
  - `kimi-agent:file-history-edit-sessions-freeze`
  - `kimi-agent:file-history-edit-sessions-unfreeze`
- **Bundled `restic` `0.19.1` Engine & Main-Process Chunks**:
  - Bundles `restic` `0.19.1` (completely absent in `3.2.28`): `Resources/restic/manifest.json` + `darwin-arm64/restic` (`29,603,376` B) on macOS `arm64`, and `resources/restic/manifest.json` + `win32-x64/restic.exe` (`31,670,288` B) on Windows `x64`, together with `assets/third-party-notices/restic-bsd-2-clause.txt`.
  - Decoded main-process bundles add `file_history_restic`, `ResticCommandError`, `restic backup: catalog snapshot verification failed`, `fileHistoryAbEligible`, and `isFileHistoryRuntimeEnabled` (`0` hits in `3.2.28`).
  - `out/main/chunks/` gains `18` new module stems (all absent in `3.2.28`): `file-history-client`, `version-diff`, `version-summary`, `repository-key-store`, `restic-resolver`, `maintenance-scheduler`, `process-supervisor`, `lease`, `ab-gate`, `content-digest`, `controller`, `image-renderer`, `pptx-diff-client`, `pptx-diff-worker`, `preview-admission`, `safe-file-access`, `status`, and `_kimi-native-addon_kimi-file-access-permissions`.
  - `out/build-manifest.json` `flavor.features` adds `"fileHistory": true` (and `"scientificRestrictedAssets": false`) on both platforms.
- **Locale Coverage (`111` of `113` New `zh-CN` Keys) & A/B Rollout Gate**:
  - Among the `113` keys newly added to `zh-CN` in `3.2.29`, **`2` keys** belong to Global Search (`showMoreMatches`, `searchOlderConversations`), and the remaining **`111` keys** belong to File/Version History and Version Comparison—covering the history panel (`historyPanelTitle: "版本历史"`, `historyInit: "初始版本"`, `historySrcKimi: "[KIMI]"`, `historySrcLocal: "[本地]"`), diff & comparison (`compareTitle: "版本比对"`, spreadsheet cell/formula recalculation diffs, PPTX slide before/after thumbnail diffs), AI change summaries (including privacy/sensitive-file exclusions and opt-in settings), one-click restore conflict/checkpoint warnings (`historyRestoreDone: "已还原到 {time} 的版本"`), and low-disk/storage maintenance recovery states.
  - Because `fileHistoryAbEligible`, `isFileHistoryRuntimeEnabled`, and `ab-gate` are wired into the runtime, **rollout may be A/B gated and the feature is not necessarily immediately visible to all users**.

Prior static analysis reported `3/3` CodeDirectory SHA-256 page hashes matching; page hashes were **not** recomputed in this verification pass. - **Windows `x64`**: Both `3.2.28` and `3.2.29` installers carry embedded PKCS#7 signatures issued to the same **Sectigo EV** subject (`Sectigo Public Code Signing Root R46 → Sectigo Public Code Signing CA EV R36 → EV leaf`, organization `北京月之暗面科技有限公司`, `serialNumber=91110108MACG2KBH8F`, 4096-bit RSA / `sha256WithRSAEncryption`) with an **RFC3161** timestamp countersignature (`OID 1.3.6.1.4.1.311.3.3.1`) and distinct per-build signature blobs. **Authenticode PE message digests were NOT recomputed**, and Sectigo root trust-chain validation and timestamp validity were **not** verified.
- **Scope & No Runtime Execution**: macOS Intel (`x64`) was not sampled; Linux is officially not provided; Android and iOS are out of scope. No target binaries were executed at runtime, and renderer-side fixes under obfuscation are strictly bounded to module-level attribution where line-level evidence is unavailable.
