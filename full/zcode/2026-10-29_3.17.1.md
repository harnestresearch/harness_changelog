## Overview

`3.17.1` is a major runtime and feature milestone (`3.17.0` was never released on CDN or GitHub; `zcode.z.ai/changelog` omitted a standalone `3.17.1` entry and later rolled its release notes into `3.17.2`). Static diffing across `3.16.3 → 3.17.1 → 3.17.2` confirms that the Electron 44 major upgrade, bundled `npm 12.2.0` runtime (`+1,677` files), `zcode-site` plugin, `sharp`-backed image annotation editor, unified remote sync, batch project management, and nearly all `3.17.x` desktop/CLI capabilities landed in `3.17.1`.

## New Desktop & UI Features

- **Image Annotation Editor (`imageEditor`) & Bundled `sharp` Native Addon**
  - Added in-preview annotation tools (pen, rectangle, ellipse, arrow, text, eraser, select/move, color palette, undo/redo) with direct export to the active chat composer (`imageEditor.*`, `17` new i18n keys; `data-image-preview-save/surface/tool/viewport` anchors).
  - Bundled unpacked native addon `app.asar.unpacked/node_modules/@img/sharp-linux-x64/lib/sharp-linux-x64.node` (`410,952` B) plus `node_modules/@img` JS packages (`12` files, `+17.1` MB).
- **Unified Remote Data Sync (`remoteSync` Refactor)**
  - Replaced `69` scattered `settings.{mcp,plugins,skills}.remoteSync.*` and `settings.remoteSync.*` keys with a unified `remoteSync.*` namespace (`101` keys) covering Commands, Hooks, MCP Servers, Plugins, Skills (including parent/child skill sync), Subagents, and Model Providers (with automatic sync on opening a project on the remote host).
  - Added sync protocol channels `user-config-sync`, `plugin-data-sync`, `skill-data-sync`, and `subagent-data-sync`.
- **Batch Project Management & Data Cleanup (`projectManagement`)**
  - Added `projectManagement.*` (`106` keys) and `project.data*` handlers supporting multi-select project removal, optional ZCode data deletion (sessions, session files, checkpoints, memories) with pre-delete size calculation and typed confirmation, local project restoration under "Removed Projects", and unread sorting/filtering.
- **Remote Server Stop / Restart / Reinstall & Compact Searchable Device List**
  - Expanded `settings.source.*` (`+24` keys) and `sourceServer.*` (`6 → 12` keys) to stop, restart, or reinstall remote ZCode Server instances (preserving projects/tasks) and filter compact device lists by name, address, or project; added `source-server-control-unresponsive`, `source-server-downgrade-unconfirmed`, `source-server-stop-failed`, and `source-server-operation-in-progress` protocol error codes.
- **Built-in `zcode-site` Official Plugin (`v0.4.2`, 16th Bundled Plugin)**
  - Added `resources/glm/packages/zcode-site-plugin/` (`25` files): MCP server `dist/server.mjs` (`595,415` B, `zcode_official` JWT auth), sidebar `sites` UI surface (`panel.html`, `872,302` B; `sidePane.sites`), `7` slash commands (`site-badge`, `site-deploy`, `site-logs`, `site-offline`, `site-online`, `site-status`, `site-usage`), and the `site-deploy` skill.
- **Plugin Batch Update & Unofficial Marketplace Risk Prompt**
  - Added `settings.plugins.updateAll*` (`done` / `partial` / `aborted`) and `marketplaces.riskWarning` / `riskAcknowledgement` (`6` keys).
- **Built-in Provider & Model Catalog Expansion (Revision `33 → 43`)**
  - Added `13` provider templates (`kimi-code-cn`, `kimi-code-intl`, `minimax-m-plan-cn`, `qwen-coding-plan-cn`, `qwen-token-plan-team-cn`, `siliconflow-cn`, `stepfun`, `stepfun-step-plan`, `tencent-tokenhub-cn`, `tencent-tokenhub-intl`, `volcengine-agent-plan`, `volcengine-ark`, `volcengine-coding-plan`); model IDs grew `167 → 203` (`+39` added including `kimi-k3.1-pro`, `MiniMax-M3.1-Flash`, `GLM-5.3`, `glm-5.3-flashx`, `DeepSeek-V4-Flash`, `doubao-seed-2.1`, `claude-haiku/opus/sonnet-5-5`, `gpt-6-luna`, `gpt-6.1-sol`, `grok-4.7`, `step-3.7-flash`, `step-5-preview`, `mimo-v2.6`; `−3` retired: `MiniMax-M2`, `MiniMax-M2.1`, `MiniMax-M2.1-highspeed`).
- **Personalization Instructions, Full Access Confirmation & Workspace MCP/Hook Trust**
  - Added Settings **Personalization** (`settings.personalization.*`, `11` keys, `100` KB local instruction limit), **Full Access (YOLO)** pre-enable risk confirmation (`mode.yoloConfirmation.*`, `11` keys), and workspace-scoped MCP/Hook trust gating (`settings.mcp.trust.*` `8` keys + `chat.workspaceMcpPending.*` + `chat.workspaceHookPending.label`).
- **File Card Actions, Full-Card Preview Open, Unread Filter, `/reload` & Mobile Log Pull**
  - Expanded `fileActions.*` (`2 → 12` keys: "Save As…" with `50` MiB cap, "Open in {application}", "More Applications…", backed by main-process `readFileIcon` / app-locator handlers), added `chat.previewCards.openCard` & `chat.message.link.openInZCode`, added unread task filtering (`viewUnread` / `noUnreadTasks`) and task/agent process restart (`recoverWorkspace`), added `/reload` (`chat.slash.app.reload`), added `pullMobileLogs` (`mobile-log-pull-request/-response/-summary`), added request-validation config read retry (`chat.configRead*`), and refined off-peak error semantics (`3102` offline-at-dispatch refund vs `3106` max runtime exceeded + `offPeakTicketExpired`).

## Agent Runtime, Protocol & Bundled Plugin Changes

- **Node-less MCP Fallback (`node-runtime/npm` + Shims)**
  - Shipped `resources/glm/node-runtime/npm/` (`npm@12.2.0`, `1,677` files) and `renderNodeFallbackShims` (`ZCODE_NODE_FALLBACK_EXEC_PATH` / `ZCODE_NODE_FALLBACK_NPM_ROOT`, POSIX & Windows shims) so stdio MCP servers run without a system Node.js installation.
- **Dynamic Workflow Quota Auto-Resume & `world.run` Output Shaping**
  - Added `startWorkflowQuotaAutoResume` (`isPlausibleQuotaResetAt`, `dynamic_workflow.quota_resume.{scheduled,failed,gave_up,refused}`) to resume quota-paused workflow runs automatically at reset time; updated `dynamic-workflows/SKILL.md` (`+1,099` B) with `world.run` `opts.output` (`"full"` / `"discard"` / `{ tail: n }`, `16` MiB cap) and `run.id` / `run.resumedFrom`.
- **`CronPauseSelf` Scheduled Automation Tool**
  - Added `CronPauseSelf` (`cronPauseSelfHandler`, available exclusively inside scheduled runs) allowing an automation to pause its own schedule when user-specified stop conditions are satisfied.
- **Official Command Endpoint, Input Prediction, Built-in Tool Rewriter & Session Residency**
  - `glm/zcode.cjs` (`+163,797` B) adds `createOfficialCommandEndpoint` (local Unix `endpoint.sock` + bearer token via `ZCODE_OFFICIAL_ENDPOINT` / `ZCODE_OFFICIAL_ENDPOINT_TOKEN` and `X-ZCode-Official-Endpoint-Error`), Protocol v4 `ConversationInputPredictionHandler`, `ProviderBuiltinToolStreamRewriter` (`zcode-provider-builtin` rewriting server-side `web_fetch`/`web_search`/`code_execution`/`tool_search_tool_*`/`advisor` blocks into renderable MCP-style tool calls), `SessionLifecycleController` (`residency: "resident-only"`, `V4SessionNotResidentError`), `x-zcode-session-features` context-owned header, local TTFT `ttft.*` telemetry keys, and Git snapshot/checkpoint hardening bypassing `26` repository Git hooks (`automaticGitArgs/Config/Env`).
- **Desktop ↔ Host Protocol & Plugin Updates**
  - Added `task-pin-request/-response`, `task-archive-request/-response`, `workspace-create-request/-response`, and `provider-provisioning-lane-request/-result` IPC schemas.
  - `node-repl-host` (`0.6.1 → 0.7.0`, `5,618,452 → 4,884,244` B via nested `node_modules` deduplication): hardened Computer Use Helper installation (`O_EXLOCK` lease lock, `ZCODE_CUA_HELPER_BUILD_ID` pinning, Apple `TeamIdentifier` verification, symlink/zip traversal guards, browser broker auth) and rewrote observe-then-act guidance.
  - `zcode-cua` (`0.6.5`): fixed `left_click_drag` `options.strategy` passthrough, removed dead `greater: ">"` key mapping, and restored `tree_shown_to_model: true` in `get_app_state` to stop false `element_index_shifted` errors.
  - `documents` (`0.2.1`), `pdf` (`0.2.2`), `presentations` (`0.2.1`), `spreadsheets` (`0.2.1`): deduplicated server bundles (`−224` KB each) and registered the `open_document` MCP tool; `visualize` (`0.1.0 → 0.1.1`) added `zcode.z.ai` to its CSP allowlist; `electron-updater` bumped `^6.8.3 → ^6.8.10`; `.deb` `postrm` fixed `update-alternatives --remove` target path (`/opt/ZCode/zcode`) and unloaded the AppArmor profile before removal.
