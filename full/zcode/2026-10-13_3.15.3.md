## Overview

Across `656` `.deb` files on Linux `x86_64`, only `4` files changed (`app.asar` `+1,151` B, `glm/zcode.cjs` `+198` B, `node-repl-host/dist/mcp/server.js` build ID, and `changelog.gz`). ## Binary-Verified Incremental Changes (`3.15.2` → `3.15.3`)

- **Auto-Updater Install Admission State Machine & Self-Recovery (`out/main/index.js`, `+1,135` B)**
  - Replaces the single `quitAndInstallInFlight` boolean and its `finally { Go = !1 }` reset—which allowed `before-quit` listeners to re-intercept shutdown and loop infinitely—with a 4-state lifecycle (`"idle"` / `"preparing"` / `"installing"` / `"recovering"`) guarded by `isUpdateTargetLocked()` (`state !== "idle"`), retaining the terminal lock until process exit.
  - Adds `recoverFromFailedUpdateInstall`: if preparation or `autoUpdater.quitAndInstall()` (now wrapped in `catch` logging `"quit and install failed"`, after re-verifying downloaded update readiness) fails after Host/Agent and remote services have already been torn down, logs `"[auto-update] install failed after shutdown started: relaunch app"` and executes `app.relaunch()` + `app.exit(0)` instead of leaving a headless zombie process.
  - Suppresses late events after install admission: `before-quit` checks `state !== "idle"`, `update-downloaded` (`publishDownloadedUpdate`) and channel resolution ignore late callbacks while locked, and `handleAutoUpdateFailure` suppresses `"Cannot check for updates: "` background check errors (`"[auto-update] ignore late check failure after install admission"`).
- **Client Request Signer Scope & Disposal Guard (`glm/zcode.cjs`, `+198` B)**
  - `ClientRequestSigningV4Manager` replaces eager closure-bound signer `entries` with lazy per-request `scopes` resolution (`this.resolveSigner(scope, …).request(…)`), marking `scope.disposed = true` before signer teardown and throwing `"Client request signer has been disposed."` immediately if a disposed scope is invoked—resolving parallel Agent / rapid model-call failures during credential rotation.
- **Official Upgrade Recovery Advisory & Onboarding Notes (`zcode.z.ai/changelog`)**
  - Official upgrade notice: upgrading *from* `3.15.1` (or `3.15.2`) executes the old shutdown path and may still hang once; download the full `3.15.3+` installer or force-quit (`⌥⌘Esc` → Force Quit on macOS; end the `ZCode` process via System Monitor on Linux, then relaunch).
  - Official notes also list fixing repeated onboarding prompts for users who already completed/skipped onboarding and preventing slow-network onboarding checks from blocking main UI entry (no separate Linux i18n/host string delta observed; likely server-side or non-literal state logic).
