## Overview

`dsh-v0.2.2-rc.5` is a **prerelease** candidate succeeding `dsh-v0.2.2-rc.4` (`5` commits, `433` files changed, `+917 / -594` lines across `53` non-manifest source/doc/upgrade-guide/test/snapshot files `+537 / -214` from PR #8707 and `380` workspace `package.json` manifests with version-only bumps, plus a zero-net-diff branch merge in PR #8595). ## Behavioral, Routing & UI Changes

- **Per-Route Search Provider Preference & Request Context Wiring (`packages/bundle/base/cordis.patch.yml`, `packages/web/web/src/{index,types}.ts`, `packages/web/tool-web/src/search.ts`, `packages/extensions/tool-cordis/src/api-catalog.ts`, PR #8707)**:
  - **Base Composition Default**: `packages/bundle/base/cordis.patch.yml` removes `searchProvider: deepseek-search-api` from the `@deepseek-ai/dsh-web` row, leaving only `fetchProvider: http` (`web_fetch` defaults and behavior are completely unchanged). Both `@deepseek-ai/dsh-web-search-deepseek` (`id: 'deepseek-official'`, `apiKeyEnv: DEEPSEEK_API_KEY`) and `@deepseek-ai/dsh-web-deepseek-api` (`id: 'deepseek-search-api'`) remain mounted in `dsh-base`.
  - **Seam Contract & Route Constants (`@deepseek-ai/dsh-web`)**:
    - Widens `WebSearchRequest` (`packages/web/web/src/types.ts` and `api-catalog.ts`) with optional `readonly llmProvider?: string`.
    - Defines module constants `DEEPSEEK_MODEL_ROUTES = new Set(['deepseek-official', 'deepseek-account'])`, `DEEPSEEK_ROUTE_SEARCH_PROVIDER = 'deepseek-official'`, and `OTHER_ROUTE_SEARCH_PROVIDER = 'deepseek-search-api'`.
    - Both `WebRuntime.search(request, signal)` and `WebRuntime.searchReady(llmProvider)` pass `llmProvider` to `selectSearchProvider(llmProvider)`, keeping step-level tool admission (`when: ({ modelSelection }) => ctx.web.searchReady(modelSelection.provider)`) and tool execution (`exec.agent?.session.requestContext()?.provider` in `applyWebSearchTool`) aligned on the same provider.
  - **Auxiliary Messages Execution Path**: On `'deepseek-official'` / `'deepseek-account'` routes, unconfigured `web_search` still runs as a Harness tool call (not an in-turn chat server tool): `runSearchQueries()` fans out `1..searchMaxQueries` distinct queries concurrently, and `DeepSeekSearchProvider` dispatches one auxiliary `POST ${baseURL}/messages` request per query (`model: 'deepseek-v4-flash'`, `max_tokens: 4096`, `thinking: { type: 'disabled' }`, `tools: [{ type: 'web_search_20250305', name: 'web_search', max_uses: 5 }]`), recording `web/deepseek-search-llm-request` in the Session log.
- **Selection Fallthrough vs. Zero Execution Fallback (`packages/web/web/src/index.ts`, `packages/web/web/tests/web.spec.ts`)**:
  - **Configured Override (`web.searchProvider` or `$DSH_WEB_SEARCH_PROVIDER` set)**: Wins on **every** route; throws `WEB_PROVIDER_CONFIGURED_MISSING` if unregistered or `WEB_PROVIDER_CONFIGURED_UNAVAILABLE` if `provider.available()` returns `false`, with zero fallback.
  - **Unconfigured (`Automatic`) Local `available()` Resolution**: Filters registered search providers by synchronous local `available()` (no network calls). If `preferredId` is in `usable`, returns `preferredId`; if `preferredId` is unregistered or locally `available() === false`, falls through to `usable[0]` **only when `usable.length === 1`**, throwing `WEB_PROVIDER_UNAVAILABLE` when `usable.length === 0` and `WEB_PROVIDER_AMBIGUOUS` when `usable.length > 1` (e.g., if `deepseek-official` is not registered while both `deepseek-search-api` and a third-party search plugin are usable on a `deepseek-official` route). Note that in shipped `dsh-base`, `DeepSeekSearchProvider.available()` checks callback/URL/integer config validity locally rather than live key validity, while missing credentials withhold `web_search` via `ready()` or fail at call time.
  - **Zero Runtime / Network Fallback**: Once `resolveProvider()` returns a provider, any credential resolution failure (`WEB_PROVIDER_CREDENTIAL_MISSING`), cancellation (`WEB_ABORTED`), HTTP error (`401`/`403`/`404`/`429`/`5xx`), redirect rejection, or missing `web_search_tool_result` block throws `WebError` (`WEB_PROVIDER_ERROR`) and **never** retries through another search provider.
- **Settings UI `Automatic` Default, 8-Locale Rename & Inline Snippets (`packages/client/ui-settings-web-search/src/client/{WebSearchCard.tsx,locales.ts}`, `packages/web/web-search-deepseek/src/{provider,types}.ts`)**:
  - **Settings Card (`WebSearchCard.tsx` & `locales.ts`)**: With no `searchProvider` composed in `dsh-base`, the Search dropdown opens on **Automatic** (`自动选择`, `AUTO_ID = ''`), followed by **DeepSeek Search API** and **DeepSeek server-side search** (`DeepSeek 服务端搜索`, replacing `DeepSeek (legacy)` / `DeepSeek（旧版）` across `en`, `zh`, `ja`, `es`, `fr`, `de`, `ru`, `pt`). When `searchAuto` (`search.auto && search.selected === AUTO_ID`) is active, the card renders `t('searchAutoHint')` plus the DeepSeek search guide link and hides provider-specific form panels. Known UI boundary: `Automatic` inspects only the composition layer and does not reflect a Host `$DSH_WEB_SEARCH_PROVIDER` env override, and `searchAutoHint` is static text assuming both official search providers are registered.
  - **Inline Result Snippets & Updated Descriptions (`web-search-deepseek`)**: `WebSearchResultItem` adds `snippet?: string | null`, and `mapAnthropicResponse()` resolves `item.snippet != null && item.snippet.length > 0 ? item.snippet : snippets.get(item.url)`. Updates `DeepSeekSearchProvider.description` in all 8 locales to *"No per-search charge, but every search uses extra model tokens. Requires a DeepSeek account or API key."* (`搜索不按次收费，每次搜索都会额外消耗模型 token。需要 DeepSeek 账号或 API Key。`) and updates `searchEndpointError()` recovery guidance to name `DeepSeek server-side search`.

## Billing Claim Boundaries & Verification Limits

- **Cannot Generalize as "Search Is Free"**:
  - On `deepseek-official` / `deepseek-account` routes under `Automatic` (or when `deepseek-official` is pinned), official documentation and UI strings state there is **no per-search invocation fee**, **not** zero cost: every search query executes a full auxiliary Messages model turn (`deepseek-v4-flash`) billed as model tokens, and returned snippets add input tokens to the main conversation turn.
  - On all non-DeepSeek routes (including DeepSeek models routed via `llm-pi-ai` / third-party endpoints), outside model requests, or when `deepseek-search-api` is explicitly selected, searches hit `/v1/tools/search` and incur per-request Search API charges under `web-deepseek-api.searchBilling` (`auto` / `account` / `api-key`).
- **Policy Statement vs. Source Proof**: Source inspection confirms client routing, payload structure, and UI/documentation copy only; actual billing rates, fee waivers, and invoice accounting are enforced solely by DeepSeek's server-side billing system or custom gateways and were **not** runtime-tested or verified against live billing statements.

## Breaking Changes & Migration Compatibility

- **Unconfigured DeepSeek-Route Search Switch & Custom Gateway Breakage (`docs/upgrade-guide/v0.2.2-rc.4/web-search-deepseek-model-default/guide.{md,zh.md}`)**:
  - `1` new upgrade-guide entry (under predecessor-tag directory `docs/upgrade-guide/v0.2.2-rc.4/`).
  - Unconfigured conversations on `deepseek-official` or `deepseek-account` switch from `deepseek-search-api` (`/v1/tools/search`, no `web/deepseek-search-llm-request` event) to `deepseek-official` (`/anthropic/v1/messages`, appends `web/deepseek-search-llm-request`).
  - **Gateway Endpoint Separation**: Unlike `deepseek-search-api` (which derives `<origin>/v1/tools` from the chat route's `baseURL`), `web-search-deepseek` resolves `web-search-deepseek.baseURL` → `$DEEPSEEK_SEARCH_BASE_URL` → `https://api.deepseek.com/anthropic/v1` independently of the chat model's `baseURL` and sends `web-search-deepseek.apiKeyEnv` (`DEEPSEEK_API_KEY`) outside `deepseek-account`. Deployments whose `deepseek-official` chat route targets a custom gateway will send that gateway key to the official DeepSeek endpoint and fail until they either save the gateway's Anthropic-compatible base URL in `web-search-deepseek.baseURL` / `$DEEPSEEK_SEARCH_BASE_URL` or pin `searchProvider: deepseek-search-api`.
- **Backward Compatibility**: Stored `web.searchProvider` settings, profile `cordis.patch.yml` overrides, `$DSH_WEB_SEARCH_PROVIDER`, `fetchProvider: http`, and Session v4 JSONL files upgrade without migration (note: selecting **DeepSeek Search API** in the UI now writes `searchProvider: deepseek-search-api` to settings because `dsh-base` no longer composes it, whereas selecting **Automatic** clears `searchProvider`).
