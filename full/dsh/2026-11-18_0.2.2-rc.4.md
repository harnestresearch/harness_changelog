## Bug Fixes & Behavioral Changes

- **DeepSeek Streamed Content-Safety Refusal Handling (`packages/llm/llm/src/error.ts`, `packages/llm/llm-deepseek/src/translate.ts`, PR #8584 / `74b0e1d9081`)**:
  - **Failure Code & Retry Policy (`@deepseek-ai/dsh-llm`)**: Added `CONTENT_REFUSED: {}` to `LLM_FAILURE_CODES` (`BuiltinLlmFailureCode`). Unlike `MALFORMED_RESPONSE: { retryChoice: true }`, `CONTENT_REFUSED` omits `retryChoice: true`, excluding it from both `DEFAULT_RETRYABLE_CODES` (`EMPTY_RESPONSE`, `RATE_LIMIT`, `SERVER`, `TIMEOUT`, `TRANSPORT`) and `RETRY_CODE_CHOICES` in settings UI / `NormalRetryPolicyConfig`.
  - **Stream Translation & Billed Usage Preservation (`@deepseek-ai/dsh-llm-deepseek`)**:
    - Previously (`0.2.2-rc.3`), `translate()` passed `delta.stop_reason === 'refusal'` on `message_delta` into `stopReason()`, immediately throwing `LlmError('DeepSeek Messages stream: unsupported stop reason refusal', 'MALFORMED_RESPONSE')` before `message_stop`—discarding accumulated token usage and misreporting a content-policy refusal as a malformed wire payload.
    - Now (`0.2.2-rc.4`), `message_delta` captures `refused = refusal(delta.stop_details)` when `delta.stop_reason === 'refusal'`—building `new LlmError("DeepSeek refused to answer under its content safety review" + (explanation ? ": " + explanation : ""), "CONTENT_REFUSED")` from string `stop_details.explanation` (e.g., `blocked: messages.1.content.0`)—still applies `updateUsage(usage, event.usage)`, and at `message_stop` computes `usage.totalTokens`, **`yield`s `{ type: 'usage', usage }` first**, and then throws `refused`.
  - **Session & Web Surface Semantics (`packages/llm/llm-deepseek/README.{md,zh.md}`, `snapshots/session/deepseek-content-refusal/`)**:
    - Normal retry policy terminates the attempt without retrying; the Web UI removes the partially streamed assistant reply, while Session persistence retains the streamed blocks, billed `{ type: 'usage' }` chunk, and `{ type: 'finish', reason: { kind: 'error', failure: { code: 'CONTENT_REFUSED', message } } }` inside `assistant/attempt` (excluded from subsequent model context) and ends the turn with `turn/end { kind: 'error', error: { code: 'CONTENT_REFUSED', message } }`.
  - **PR Commit History & Net-Diff Verification**: Intermediate commits `f250e23202e` and `15762ffc037` on PR #8584 temporarily added `safety_check: { level: 'high' }` serialization, which final PR commit `e68c0334939` completely reverted (`config.ts`, `serialize.ts`, `types.ts`, and `wire-types.ts` have `0` net diff lines vs. `dsh-v0.2.2-rc.3`, and `loader-composition.spec.ts` asserts `expect(server.requests[0]).not.toHaveProperty('safety_check')`).
- **Desktop LiveShare Owner-Gateway Worker Node Mode (`packages/experimental/liveshare/src/host/tunnel-worker.ts`, PR #8634 / `f0f05ba737a`)**:
  - **Root Cause**: In the opt-in optional bundle `@deepseek-ai/dsh-experimental-liveshare`, `gatewayWorkerCommand()` (`tunnel-supervision.ts`) resolves `executable: process.execPath` with `lib/owner-gateway/cli.js` (or `--import tsx/esm ../owner-gateway/cli.ts`). Under `@deepseek-ai/dsh-desktop` (`mac` & `win`), the Host runs inside the Electron binary (`DeepSeek Harness`) via `ELECTRON_RUN_AS_NODE=1`. Because `TunnelWorker.start()` previously constructed a restricted child `env` (`NODE_ENV`, `LIVESHARE_TUNNEL_MODE: 'gateway'`, plus `WORKER_TRANSPORT_ENV` proxy/CA variables) without `ELECTRON_RUN_AS_NODE`, Electron booted the child as a second GUI shell instance that `acquireDesktopSingleInstance()` (`apps/desktop/src/single-instance.ts`) immediately quit (`exit code 0`) before IPC readiness—leaving `probeRelayPublish` / `add-share` perpetually unsettled while `TunnelWorker` looped on reconnect backoff.
  - **Fix**: Added `workerNodeModeEnv(source)` returning `{ ELECTRON_RUN_AS_NODE: mode }` when `source.ELECTRON_RUN_AS_NODE !== undefined` and `{}` otherwise, spreading it into `spawn(..., { env })` in `TunnelWorker.start()`. Covered by unit tests in `packages/experimental/liveshare/tests/tunnel-worker.spec.ts` verifying both `ELECTRON_RUN_AS_NODE='1'` forwarding and omission when `undefined`.
- **LiveShare Credential Horizon Wall-Clock Test Fix (`packages/experimental/liveshare/tests/owner-credential-horizon.host.spec.ts`, PR #8638 / `9176a089533`, Fixes #8465)**:
  - Replaced static `START = Date.parse('2026-10-15T00:00:00.000Z')` (`LIVE = START + 30d = 2026-11-14T00:00:00.000Z`, which began failing against `Date.now()` in host horizon checks on `2026-11-14`) with `PAST = new Date(Date.now() - DAY).toISOString()` and `LIVE = new Date(Date.now() + 30 * DAY).toISOString()`.

## Breaking Changes

- **`CONTENT_REFUSED` Replaces `MALFORMED_RESPONSE` for DeepSeek Stream Refusals (`docs/upgrade-guide/v0.2.2-rc.3/deepseek-refusal-code/guide.{md,zh.md}`)**:
  - `1` new upgrade-guide entry (placed under `docs/upgrade-guide/v0.2.2-rc.3/` per DSH's predecessor-tag directory convention for breaking contract changes after `v0.2.2-rc.3`).
  - Consumers inspecting LLM stream error finishes or failed `turn/end` error codes for DeepSeek `stop_reason: "refusal"` streams now receive `CONTENT_REFUSED` instead of `MALFORMED_RESPONSE` and must branch on `CONTENT_REFUSED` to surface a provider refusal notice.
- **No Persistence, Config, or CLI Breaking Changes**: Session JSONL schema remains `version: 4`, and existing `cordis.yml` profiles, CLI arguments, and Desktop installations upgrade in place without migration.
