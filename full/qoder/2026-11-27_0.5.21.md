  - The decoded worker runtime string lists for `0.5.20` and `0.5.21` both contain exactly `13,966` entries and are **completely identical** (`+0 / −0`). This is consistent with the absence of new worker-side strings for any of the four official fixes or the proxy-diagnostic re-run prompt.

## Verification Scope & Limitations

- **Covered vs. Uncovered Targets**: Analyzed packages are limited to official `releases/0.5.21/` macOS `arm64` (`Qoder-mac-arm64.zip`), Windows `x64` (`Qoder-win-x64-user.exe` + `Qoder-win-x64-user-app.zip`), and Linux `amd64` (`Qoder-linux-amd64.deb`). `Qoder-linux-x86_64.rpm` was recorded from manifest/HEAD metadata only (not downloaded, not analyzed). `Qoder-mac-x64.zip` exists on the official CDN (`348,979,444` B) but was neither downloaded nor analyzed, and macOS `arm64` results are not extrapolated to `x64`. `Qoder-win-arm64-user.exe` returned HTTP `404`. Android and iOS are outside the scope of this desktop release entry.
- **No Disassembly / No Runtime Execution**: The Windows NSIS bootstrapper was not disassembled, no client binary or worker runtime was executed, and report-only granular counts (`app.asar` `+13,300` B, `electronMain.js` `+9,814` B, renderer `+1,001` literals, `1,109`/`1,101` file trees, `context-plugin`/`office-xlsx` swaps, `14,832` B Authenticode table, `.deb` `control`, and `93` folded re-signed binaries) are attributed to the static diff report rather than independently re-unpacked. Official fixes without new plaintext strings remain statically unverifiable.
