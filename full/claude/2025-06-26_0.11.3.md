## Overview

CDX officially renamed to DXT (Desktop Extension): extension registry, blocklist enforcement, signature verification, and auto-update framework put in place; simultaneously launched the Statsig event telemetry channel and switched the main bundle to hashed chunk loading.

## Changes

- **Dependencies**: @anthropic-ai/cdx and cdx-registry renamed to @anthropic-ai/dxt 0.1.0-dev + @anthropic-ai/dxt-registry; @anthropic-ai/claude-cli upgraded to ^1.0.30-dev; added react-markdown ^9.0.3
- **Components & Native Modules**: Info.plist file association `.cdx` → `.dxt`, name "Claude Desktop Extension" → "Desktop Extension" (dxt.icns)
- **Main Process (`app.asar`)**: +10 -8 ~18 (renames 0). Build artifact restructuring: index.js shrank from 1,639,211 B to a 570 B require stub, splitting the main body into hashed chunks `.vite/build/index-PFx-bx_-.js` (1,945,865 B) + index-CSGMxIwo.js (4,984 B) (marking the start of hashed Vite build output naming); settings.html +231/-115; window-shared.css updated across the board
- **UI & Experience**: DXT extension security and management: extension blocklist (three-tier blocking by ID, content hash, and signing certificate fingerprint, cached locally in extensions-blocklist.json, with a "Blocked Extensions Removed" dialog), extension update checks ("Extensions Update Cache", "Button to update extension to specific version"), unsigned / directory mode controls (dxtRequireSignatures and isDxtDirectoryEnabled config options); extension details rendered via react-markdown
- **Network & Endpoints**: Added Statsig telemetry endpoint https://statsig.anthropic.com/v1/log_event; https://anthropic.com/engineering/desktop-extensions (official DXT blog post link)
