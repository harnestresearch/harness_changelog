## 核心亮点

- **按模型路由自动选择网页搜索提供方与设置项更名** _（对应官方说明「DeepSeek 模型使用 DeepSeek 服务端搜索，搜索不按次收费；其他模型默认使用 DeepSeek Search API」的源码实证）_：基础组合不再固定 `web.searchProvider: deepseek-search-api`；**插件 → 官方 → 网页搜索与获取** 的网页搜索提供方默认改为 **自动选择**，未固定提供方时在内置 `deepseek-official` 与 `deepseek-account` 两条模型路由上选用 **DeepSeek 服务端搜索**（`deepseek-official`，8 语种界面统一由 **DeepSeek（旧版）** 更名），在其他模型路由及非模型调用中选用 **DeepSeek Search API**（`deepseek-search-api`），网页获取仍默认本机 `http`。
- **DeepSeek 服务端搜索支持直接提取结果项内联 `snippet` 摘要** _（源码实证，官方说明未单列）_：`@deepseek-ai/dsh-web-search-deepseek` 新增优先提取 `web_search_result` 条目自带的 `snippet` 字段，仅在条目无摘要时回退关联文本块的 `citations[].cited_text`，解决 Anthropic 兼容端点 `/anthropic/v1/messages` 返回不带 `citations` 文本块时搜索来源缺少网页摘要的问题。

## 官方发布说明与源码实证对照

### 官方 Release 声明（`dsh-v0.2.2-rc.5`）

- `DeepSeek 模型使用 DeepSeek 服务端搜索，搜索不按次收费；其他模型默认使用 DeepSeek Search API。 @LegGasai`（*"DeepSeek models use DeepSeek server-side search with no per-search charge; other models default to DeepSeek Search API. by @LegGasai"*）

### 源码实证的路由、回退、迁移与计费边界（`dsh-v0.2.2-rc.4..dsh-v0.2.2-rc.5`）

- **路由判定边界（按提供方路由 ID 匹配，而非按模型名称匹配，PR #8707）**：
  - `WebRuntime`（`@deepseek-ai/dsh-web`）检查的是 `WebSearchRequest.llmProvider`（由 `@deepseek-ai/dsh-tool-web` 从 `session.requestContext()?.provider` 注入，并与步骤准入 `searchReady(modelSelection.provider)` 一致）是否命中固定集合 `{'deepseek-official', 'deepseek-account'}`，**并不检查模型名字符串**。
  - 因此，若经由 `@deepseek-ai/dsh-llm-pi-ai` 自定义/第三方 OpenAI 或 Anthropic 兼容路由接入 DeepSeek 模型，或在模型请求之外直接调用 `ctx.web.search()`（`llmProvider === undefined`），未固定搜索提供方时仍默认走 `deepseek-search-api`，并非所有名为 DeepSeek 的模型配置都走同一路径。
- **回退条件（仅限本地 `available()` 单一可用顺延，绝无执行期网络/跨提供方回退）**：
  - **显式配置时**：配置了 `web.searchProvider` 或 `$DSH_WEB_SEARCH_PROVIDER` 时对所有路由生效，未注册抛 `WEB_PROVIDER_CONFIGURED_MISSING`，本地 `available() === false` 抛 `WEB_PROVIDER_CONFIGURED_UNAVAILABLE`，不做任何回退。
  - **未配置（自动选择）时**：在本地同步 `available()` 可用集合中优先命中当前路由偏好的提供方；仅当该偏好提供方未注册或本地 `available() === false` 且剩余已注册可用提供方**恰好只有 1 个**时才选用该唯一可用项（剩余多个抛 `WEB_PROVIDER_AMBIGUOUS`，无可用项抛 `WEB_PROVIDER_UNAVAILABLE`）。
  - **执行期零回退**：一旦选定提供方，鉴权缺失、HTTP 报错或端点不兼容均直接抛出结构化 `WebError`（`WEB_PROVIDER_ERROR` / `WEB_PROVIDER_CREDENTIAL_MISSING` / `WEB_ABORTED`），**绝不会**在运行时自动改走另一搜索提供方。
- **计费说明边界（不可泛化为「搜索免费」，且源码不证明实际账单）**：
  - **不按次收费 ≠ 搜索免费**：官方说明与提供方文案明确 `deepseek-official` 服务端搜索仅免收**按次调用费**，但每个去重查询仍会向 `/anthropic/v1/messages` 发起一次独立的辅助模型请求（默认 `deepseek-v4-flash`、`max_tokens: 4096`、单请求至多 `maxUses: 5` 次服务端搜索），**每次搜索都会额外消耗辅助模型 token**（`搜索不按次收费，每次搜索都会额外消耗模型 token`），且返回摘要进入主会话上下文同样计入主模型输入 token；而其他路由或手动选定的 `deepseek-search-api` 仍按请求产生 Search API 费用。
  - **证据边界**：客户端源码仅控制请求路由与界面提示文案，实际是否免除按次费、token 计价与扣费账单完全取决于远端 DeepSeek 服务端或自定义网关策略，本汇总**未做运行时或真实账单验证**。

## 破坏性变化与迁移说明

- **默认搜索路径切换与自定义网关端点分离（`docs/upgrade-guide/v0.2.2-rc.4/web-search-deepseek-model-default`）**：
  - 未配置 `web.searchProvider` 的 `deepseek-official` / `deepseek-account` 会话搜索由 `/v1/tools/search` 切换为辅助 `/anthropic/v1/messages` 请求（会话日志现会追加 `web/deepseek-search-llm-request` 事件）。
  - **自定义网关注意**：与跟随模型路由 origin 的 `deepseek-search-api` 不同，`web-search-deepseek` 的端点独立解析为 `web-search-deepseek.baseURL` → `$DEEPSEEK_SEARCH_BASE_URL` → `https://api.deepseek.com/anthropic/v1`（非账号路由默认发送 `DEEPSEEK_API_KEY`）。将 `deepseek-official` 聊天路由指向代理/网关的部署若未同步配置 `web-search-deepseek.baseURL` / `$DEEPSEEK_SEARCH_BASE_URL` 或固定选用 **DeepSeek Search API**（`searchProvider: deepseek-search-api`），搜索请求会携网关密钥发往官方端点并失败。
  - **既有配置与持久化兼容**：已保存的 `web.searchProvider`、部署 `cordis.patch.yml` 覆盖项、`$DSH_WEB_SEARCH_PROVIDER`、`fetchProvider: http` 以及 Session v4 JSONL 会话文件均保持兼容，升级不会改写已有选择。
