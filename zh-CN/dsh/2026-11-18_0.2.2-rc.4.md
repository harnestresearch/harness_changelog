## 核心亮点

- **DeepSeek 流式内容安全拒答独立错误码 `CONTENT_REFUSED` 与计费用量保留** _（对应官方说明「优化模型请求收到异常消息响应时的表现」的源码实证）_：当 DeepSeek Messages 流以 `stop_reason: "refusal"` 结束时，`@deepseek-ai/dsh-llm-deepseek` 现先上报拒答前已消耗的计费 token 用量，再以不可自动重试的新错误码 `CONTENT_REFUSED`（附带提供方 `stop_details.explanation`，如被拦截的图片位置）结束本轮，而不再在流中途误报为协议格式错误 `MALFORMED_RESPONSE` 并丢弃用量；Web 端自动撤回已流式输出的部分草稿，会话日志将其保留在模型上下文历史之外的 `assistant/attempt` 中。
- **桌面端 LiveShare 隧道子进程 `ELECTRON_RUN_AS_NODE` 修复** _（对应官方说明「修复 LiveShare 在桌面端无法创建分享的问题」的源码实证）_：修复实验性插件 `@deepseek-ai/dsh-experimental-liveshare` 在 `mac` / `win` Electron 桌面端拉起 owner-gateway 网关子进程（`process.execPath`）时未透传 `ELECTRON_RUN_AS_NODE`，此前会导致子进程作为第二个桌面 GUI 实例启动并被单实例锁立即退出（退出码 `0`），使分享始终无法完成注册。

### 源码 Diff 实证机制与边界（`dsh-v0.2.2-rc.3..dsh-v0.2.2-rc.4`）

- **DeepSeek 流式内容拒答分类与用量结算（`@deepseek-ai/dsh-llm-deepseek` 与 `@deepseek-ai/dsh-llm`，PR #8584）**：
  - **精确作用范围**：官方表述泛称为「异常消息响应」，源码实际仅针对 DeepSeek Messages SSE 流结束原因为 `delta.stop_reason === "refusal"` 的内容安全拒答场景。真实协议违例仍抛 `MALFORMED_RESPONSE` 或 `STREAM_CLOSED`，无内容块的正常终止仍抛 `EMPTY_RESPONSE`，流式输出前被拦截的输入仍按 HTTP `400` 报 `INVALID_REQUEST`；发出的请求体未新增任何 `safety_check` 字段，其他模型提供方适配器亦无改动。
  - **处理机制**：在 `message_stop` 处先产出汇总后的 `{ type: 'usage' }` 分块（含输入/输出/缓存及 `totalTokens`），再抛出 `LlmError("DeepSeek refused to answer under its content safety review...", "CONTENT_REFUSED")`（若 `stop_details.explanation` 存在则拼接说明）。`CONTENT_REFUSED` 不标记 `retryChoice: true`，默认重试策略直接结束当前尝试而不做无效重试。
- **桌面端 LiveShare 网关工作进程继承 Electron Node 模式（`@deepseek-ai/dsh-experimental-liveshare`，PR #8634）**：
  - `TunnelWorker.start()` 启动 `process.execPath` 时新增 `workerNodeModeEnv(process.env)` 透传宿主自身的 `ELECTRON_RUN_AS_NODE`。在 `@deepseek-ai/dsh-desktop`（`mac` / `win`）下使 `owner-gateway/cli.js` 以 Electron Node 模式运行，避免触发第二个 GUI 实例被 `requestSingleInstanceLock()` 提前终止及监督器无限退避重拉；纯 Node CLI/Web 宿主（未设置 `ELECTRON_RUN_AS_NODE`）的子进程环境保持不变。
- **LiveShare 凭据有效期测试时钟修复（PR #8638，官方说明未单列）**：
  - `owner-credential-horizon.host.spec.ts` 将硬编码的 `2026-10-15` + 30 天（`2026-11-14` 后过期失败）改为基于 `Date.now()` 的相对偏移（仅测试文件改动，不影响运行时）。

## 破坏性变化

- **SDK / 事件消费侧错误码变更（`CONTENT_REFUSED`，`docs/upgrade-guide/v0.2.2-rc.3/deepseek-refusal-code`）**：
  - 对 LLM 流错误结束块（`finish`）或失败轮次 `turn/end` 错误码进行分类处理的 SDK/集成方，在遇到 DeepSeek 流式 `stop_reason: "refusal"` 时收到的错误码由 `MALFORMED_RESPONSE` 变为 `CONTENT_REFUSED`，需同步识别 `CONTENT_REFUSED` 并提示提供方拒答。
  - **无终端配置或持久化格式破坏**：既有 Session v4 JSONL 会话文件、`cordis.yml` 配置、CLI 参数及桌面端安装均可从 `0.2.2-rc.3` 原地无缝升级。
