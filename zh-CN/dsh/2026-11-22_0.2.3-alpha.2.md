## 核心亮点

- **将 Node.js 要求提高至 `^24.22.3 || >=26.13.1` 以对齐 2026 年 11 月 `undici` 安全修复** _（对应官方说明的源码实证）_：将根 `package.json` 与 `@deepseek-ai/dsh`（`apps/cli/package.json`）中的 `engines.node` 从 `>=24.9.0` 调整为 `^24.22.3 || >=26.13.1`，使系统 Node 运行时与首批包含 2026 年 11 月 `undici` 安全修复的版本对齐（Node `24.22.3` 内置 `undici 7.30.2`；Node `26.13.1` 内置 `undici 8.12.4`）。
  - **各主版本允许与排除关系**：允许 **`24.x` 中 `>=24.22.3`**（并非仅等于 `24.22.3`）以及 **`>=26.13.1`**（semver 语义下允许 `26.13.1+` 及无上限的 **`27.x` 及以上**，但 CI 仅覆盖 `24.22.3`、最新 `24.x` 与浮动 `26`）；排除 **`<24.22.3`**（Node 20/22/23 及 `24.0.0`–`24.22.2`）、**整个 `25.x` 系列**（因 `^24.22.3` 隐含 `<25.0.0-0` 上界），以及 **`26.0.0`–`26.13.0`**。
  - **实际检查位置与拦截力度**：主要为包管理器清单声明（仓库未配置 `engine-strict=true`）；**DSH CLI 启动代码本身没有任何运行时 `process.versions.node` 拦截**，Python SDK 仅开发使用的 `DSH_RUNTIME_MODE=node` 启动器也只更新了缺少 `node` 时的提示文案而未校验版本号。严格等于 `=== '24.22.3'` 仅在 CI 构建兼容性门禁（显式设置 `DSH_NODE_COMPAT_BUILD=1` 时）以及内置主运行时 / Python 单文件可执行产物打包脚本中生效。
- **同步升级内置运行时、Electron `^44.11.5`、`undici` 覆盖及 9 个 vendor 预发布版本** _（源码实证，官方说明未单列）_：在工作区 `overrides` 与直接依赖中统一升级 `undici` 至 `6.29.1` / `7.30.2` / `8.12.4`；桌面端 Electron 由 `^44.7.0` 升至 `^44.11.5`（内嵌 Node `24.22.3`）并配套升级 `node-addon-require-builtin` 至 `^0.1.10`；将主运行时锁文件与 Python SDK 单文件可执行构建器精确固定为 Node `24.22.3`；同时将 9 个内部 Cordis/Cosmokit/Schemastery vendor 包升至 `*-alpha.1`。**相较 `0.2.3-alpha.1`，无任何面向用户的 UI、CLI、协议、工具或插件功能变化。**

## 官方发布说明与源码实证对照

### 官方 Release 声明（`dsh-v0.2.3-alpha.2`）

- `调整 Node.js 版本要求为 24.22.3，26.13.1 及以上版本。 @imccyu`（*"DSH now requires Node.js 24.22.3 or later in the 24.x series, or 26.13.1 or later. by @imccyu"*）

### 源码实证的版本范围辨析与作用边界（`dsh-v0.2.3-alpha.1..dsh-v0.2.3-alpha.2`）

- **中英文发布说明精确度辨析**：中文说明「`24.22.3，26.13.1 及以上版本`」易被误读为 `24.22.3` 严格相等或包含 `25.x`。源码 `engines.node` 精确写法为 `^24.22.3 || >=26.13.1`（与英文说明一致），按 semver 等价于 `>=24.22.3 <25.0.0-0 || >=26.13.1`：
  - **`24.x`**：允许 `>=24.22.3` 的全部 `24.x` 版本（如 `24.22.3`、`24.22.4`、`24.23.0`，并非仅等于 `24.22.3`）；不再支持 `24.0.0`–`24.22.2`。
  - **`25.x`**：**不允许**（被 `^24.22.3` 的 `<25.0.0-0` 上界与 `>=26.13.1` 下界共同排除；而上版 `>=24.9.0` 曾从语义上放行 `25.x`）。
  - **`26.x`**：排除 `26.0.0`–`26.13.0`；允许 `26.13.1` 及更高 `26.x`。
  - **`27.x` 及以上**：**semver 声明允许**（`>=26.13.1` 未设主版本上界），但 **CI 未验证**（CI `node-compat` 矩阵仅测固定 `24.22.3` 与浮动 `26`）。
- **受影响与不受影响的分发形态**：
  - **受影响（需升级宿主 Node.js）**：npm `@deepseek-ai/dsh` 安装、源码检出、CI/容器环境，以及 Python SDK 显式指定 `DSH_RUNTIME_MODE=node` 的开发载体。
  - **不受影响（自带 Node `24.22.3` 运行时）**：打包后的 `@deepseek-ai/dsh-desktop` 桌面应用（基于 Electron `^44.11.5` 及锁定的主运行时 `nodeVersion: 24.22.3`）与 Python SDK 内置单文件可执行产物（现已精确固定嵌入 `node24.22.3-<platform>-<arch>`）。
  - **独立原生扩展未变**：`@deepseek-ai/node-addon-system*` 仍保持 `engines.node: ">=20"`。
- **除运行时下限与依赖外无功能改动**：`packages/*/*/src` 下仅更新了 3 行注释（`app-boot`、`hmr`、`ptc-runtime-node`），用于 Node `<24.12` 的旧 v1 ESM 加载器适配代码仍保留在源码中（注释标记为受支持运行时下不可达）。

## 破坏性变化与迁移说明

- **Node.js 最低版本上调（`docs/upgrade-guide/v0.2.3-alpha.1/node-24-22-3/guide.{md,zh.md}`）**：
  - 新增 `1` 条双语升级指南（目录沿用 `v0.2.3-alpha.1/` 归档，但合入于 `alpha.1` 标签之后并随 `dsh-v0.2.3-alpha.2` 首次发布）。
  - 使用 npm 安装、源码检出或 `DSH_RUNTIME_MODE=node` 且宿主 Node 处于 `<24.22.3`、`25.x` 或 `26.0.0`–`26.13.0` 的环境，需先升级宿主 Node.js 至 **`24.22.3+`（24.x）** 或 **`26.13.1+`**，用 `node --version` 核对，源码检出需重跑 `pnpm install`。
  - 相较 `0.2.3-alpha.1`，无配置文件、profile、Session v4 JSONL 或插件 API 破坏性变更。
