## 概述

`3.15.3` 是 `2026-10-13` 当日发布的第二轮热修（距 [3.15.2](2026-10-13_3.15.2.md) 约 5.5 小时）。Linux `x86_64` 全包 `656` 个文件中仅 `4` 个文件变化（`app.asar` `+1,151` B、`glm/zcode.cjs` `+198` B、`node-repl-host/dist/mcp/server.js` 构建身份串及 `changelog.gz`）。二进制差分（`3.15.2 → 3.15.3`）确认本版专门修复 `out/main/index.js`（`+1,135` B）自动更新退出卡死与 `glm/zcode.cjs`（`+198` B）并行请求签名器释放竞争，而官网 `3.15.3` 页面合并列出的登录/连接套餐鉴权修复已在 [3.15.2](2026-10-13_3.15.2.md) 落地。

## 二进制核实的净增变更（`3.15.2` → `3.15.3`）

- **自动更新安装准入状态机与失败自恢复（`out/main/index.js`，`+1,135` B）**
  - 移除单布尔标记 `quitAndInstallInFlight` 及其在 `finally { Go = !1 }` 中提前复位的缺陷（该复位会导致 `before-quit` 监听器重复拦截退出并形成无限重入卡死），升级为 `"idle"` / `"preparing"` / `"installing"` / `"recovering"` 四态状态机与 `isUpdateTargetLocked()` 门控，成功交接安装后锁定终态直至进程退出。
  - 新增 `recoverFromFailedUpdateInstall`：当退出准备已关闭 Host/Agent 与远控服务后，若安装就绪复查未通过或 `autoUpdater.quitAndInstall()` 抛错（新增 `catch` 捕获 `"quit and install failed"`），记录 `"[auto-update] install failed after shutdown started: relaunch app"` 并立即调用 `app.relaunch()` + `app.exit(0)` 重启恢复，避免无界面僵尸进程残留。
  - 新增迟到事件抑制：安装准入后拦截重复 `before-quit`、忽略迟到的 `update-downloaded`（`publishDownloadedUpdate`）与通道改写，并将后台 `"Cannot check for updates: "` 错误分流抑制。
- **客户端请求签名器懒解析与废弃守卫（`glm/zcode.cjs`，`+198` B）**
  - `ClientRequestSigningV4Manager` 将闭包急切绑定的 `entries` 改为按请求懒解析的 `scopes` 记录，并在 `dispose()` 时先置 `disposed = true` 再释放签名器（已废弃 scope 调用立即抛出 `"Client request signer has been disposed."`），修复凭据更新期间多 Agent 并行或连续调用模型时的请求异常失败。
- **官方升级恢复提示与新手引导修复说明（`zcode.z.ai/changelog`）**
  - 官方升级提示：从 `3.15.1`（或 `3.15.2`）触发升级时仍执行旧版退出代码，若出现卡住请前往官网下载完整安装包，或手动强制退出（macOS 按 `⌥⌘Esc` 强制退出 ZCode；Linux 通过系统监视器结束 `ZCode` 进程后重启）。
  - 官网同条列出「修复已完成或跳过新手引导的用户被重复弹出引导」与「网络较慢时不再因引导判断被卡住」（Linux 包内 i18n 与主/宿主字面量零新增，推测为服务端策略或非字面量状态改动）。
