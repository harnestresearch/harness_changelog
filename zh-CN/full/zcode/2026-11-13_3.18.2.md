## 概述

承接上一正式版 [3.17.2](2026-11-02_3.17.2.md) 的 `3.18.x` 系列官方正式发布版本（官方发行说明累计共 56 条 = 预览版 [3.18.0](2026-11-10_3.18.0.md) 42 条 + 预览版 [3.18.1](2026-11-11_3.18.1.md) 10 条 + `3.18.2` 新增 4 条）。基于预览版 `3.18.1-10376`（相距约 21.5 小时）的静态二进制对比表明，`3.18.2` 为定向凭据、账号与更新器热修补丁：Linux `x86_64` 包内 Electron 运行时与全部原生模块实现比特级零改动；应用层增量全部集中于 `app.asar`（`+12,780` B）与 `glm/zcode.cjs`（`+2,722` B），围绕三条凭据/登录链路展开——数据目录迁移后的凭据密钥共享 IPC、Linux 无系统密钥环时的私有文件密钥回退，以及 Start Plan 账号材料独立化与 `zai_cn` → `bigmodel` 家族映射——并同步包含一项 Windows 检查更新路径与权限兼容性修复。

## 凭据、账号与更新器修复（底层新增机制）

- **数据目录迁移后凭据密钥共享（`credential-key-share` IPC）**
  - 设置服务 `updateDataBaseDir` 在完成数据目录拷贝后新增调用 `shareCredentialKeyWithDataRoot`，通过宿主↔主进程 worker 端口发送经 Zod 严格校验的 `credential-key-share-request`（`{ type, requestId: uuid, targetBaseDir: string(1..32767) }`）。
  - 主进程 `spawnHostProcess`（`out/main/index.js`）校验 `targetBaseDir` 为绝对路径（否则拒绝并报错 `"Data root must be absolute"`）后，对 `<newRoot>/.zcode/v2/credentials.json` 执行 `shareKeyWithCopiedCredentials`：借助新增助手 `keyFingerprint` / `encodedKeyFingerprint` / `readOsKeyFingerprints` 比对源与目标凭据文件中 `enc:v2:os:<24hex>:` 密文内嵌的 OS 密钥环指纹集及 `isOsSourcePinned`（`credential-source` 内容为 `"os\n"`）绑定状态，一致时将源侧 OS 密钥环密钥以 `base64url` 写入目标凭据文件旁的 `.keyring` 存储，使迁移后的加密凭据无需重建系统密钥环项即可继续解密。
  - 返回 `credential-key-share-result`（`ok` 或 `errorCode: "CREDENTIAL_SECURE_STORAGE_UNAVAILABLE"`）并记录 `[credential-key-share] completed|failed`。协议同步注册至 8 个预加载脚本中的 7 个（`out/preload/{index,codingPlanWebview,cuaPermissionPanel,embeddedBrowserJavaScriptDialog,pluginSandbox,resourceManager,rewardsWebview}.cjs`）、`out/scheduler/index.js`、主进程/宿主共享消息块（`chunk-N4BDK3A6.js` / `chunk-IEBWXNOE.js`）及 CLI 运行时（导出 `hostCredentialKeyShareRequestResponseSchema` / `hostCredentialKeyShareResultMessageSchema`）。
- **Linux 系统凭据库不可用时的私有文件密钥回退（`enablePrivateFileKeyFallback`）**
  - 凭据加密模块 `createSystemCredentialCipher` 的 `getKey` 失败分支新增回退：当 OS keyring 读写校验失败、凭据源未钉死在 `os`/`env` 且回退钩子已武装时，调用 `publishPrivateSecretFile` 生成 32 字节随机 `base64url` 密钥，以 `0600` 权限（`mode: 384, flag: "wx"`）独占写入 `<dataRoot>/.zcode/v2/credential-secret.<pid>.<hex>.tmp` 后原子改名为 `credential-secret`（容忍 `EEXIST`），随后改由受管文件/环境源读取密钥（返回 `source: "env"`）并触发 `onFallback`。
  - **三副本接线状态**：桌面 **主进程副本**（`out/main/chunk-5SVAX2QO.js`）已在 `out/main/index.js` 的 `process.platform === "linux"` 启动路径中调用 `enablePrivateFileKeyFallback` 完成接线武装（回退触发时输出 `[credential] Linux 系统凭据库不可用，已改用私有文件密钥`；若开启前凭据已被访问 `Zd.size > 0` 则告警拒绝切换）；**宿主副本**（`out/host/index.js`）与 **CLI 副本**（`glm/zcode.cjs`）虽同步携带同源回退分支，但钩子变量零赋值、在当前发行版中静态不可达。
- **Start Plan（入门套餐）账号材料独立化与 `zai_cn` → `bigmodel` 映射**
  - 宿主进程（`out/host/index.js`，`+3,862` B）新增 `loadStartPlanMaterial` 与 `startPlanMaterialFromSnapshot`，在无需完整 OAuth `accessToken` 的情况下返回独立材料 `{ family, loginProvider, zcodeUserId, sessionRevision, accountIdentity, zcodeJwtToken }`，并将 `start-plan` 的 API Key 推导由 `loadOAuthTokenSet(family)` 切换至专用 `loadStartPlanZcodeJwt(family)`。
  - `createCodingPlanFamilyAvailabilityResolver` 扩展为对 `accountMaterial` 与 `startPlanMaterial` 执行双重一致性校验（`project_token_scope_invalidated`），`resolveStartPlanAuthorization` 改读 `startPlanMaterial?.zcodeJwtToken`；新增 `isStartPlanFamilyCurrent` 与按套餐类型分流的 `identityOf("start-plan")`，避免因缺少家族级 `individual-coding-plan` 身份而将 Start Plan 误判为 `coding_plan_not_connected`。
  - 新增 `resolveStartPlanFamilyFromOAuthProvider`（`out/host/chunk-IEBWXNOE.js` 及 `glm/zcode.cjs` 导出），将 `3.18.0` 引入的国内 OAuth 供应者 `zai_cn` 显式归入 `"bigmodel"` 起始套餐家族。
- **Windows 更新器兼容性修复（官方发行说明）**
  - 修复 Windows 在受系统限制或安装/用户目录路径包含特殊字符时检查更新失败的问题。

## 构建与组件状态

- **运行时、依赖树与多语言零变动**：
  - Linux `x64` 包内全部 17 个 Electron/Chromium 运行时文件及 4 个 unpacked 原生模块（`sharp-linux-x64.node`、`keyring.linux-x64-gnu.node`、`pty.node`、`sshcrypto.node`）与 `3.18.1` 的 SHA-256 逐一完全相同。
