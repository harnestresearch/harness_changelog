## 概述

`dsh-v0.2.2-rc.5` 是承接 `dsh-v0.2.2-rc.4` 的 **预发布候选版本（Prerelease）**，共包含 `5` 个提交、改动 `433` 个文件（`+917 / -594` 行，其中 PR #8707 贡献全部 `53` 个非 `package.json` 的源码/文档/升级指南/测试/快照文件改动 `+537 / -214` 行，发版提交仅更新 `380` 个工作区 `package.json` 版本号 `+380 / -380` 行，另有 `1` 个相对 `rc.4` 净改动为 `0` 的分支合并 PR #8595）。本版移除 `packages/bundle/base/cordis.patch.yml` 中写死的 `searchProvider: deepseek-search-api`，由 `@deepseek-ai/dsh-web`（`ctx.web`）与 `@deepseek-ai/dsh-tool-web`（`web_search`）在未显式配置搜索提供方时按调用会话的 **LLM 提供方路由 ID** 自动分流（`DEEPSEEK_MODEL_ROUTES`：`deepseek-official` 与 `deepseek-account` → `deepseek-official` Messages 服务端搜索；其他路由及模型请求外调用 → `deepseek-search-api`），将 Web 设置页搜索提供方默认项切为 **自动选择** 并把 8 语种下的 **DeepSeek（旧版）** 统一更名为 **DeepSeek 服务端搜索**，为 `@deepseek-ai/dsh-web-search-deepseek` 补齐结果条目自带 `snippet` 字段的直接提取能力，并新增 `1` 条针对默认搜索切换与自定义网关配置边界的 `docs/upgrade-guide` 记录。

## 路由、回退与界面行为变更

- **按模型路由自动选择搜索提供方与请求上下文透传（`packages/bundle/base/cordis.patch.yml`、`packages/web/web/src/{index,types}.ts`、`packages/web/tool-web/src/search.ts`、`packages/extensions/tool-cordis/src/api-catalog.ts`，PR #8707）**：
  - **基础组合默认值变更**：`packages/bundle/base/cordis.patch.yml` 从 `@deepseek-ai/dsh-web` 配置段移除 `searchProvider: deepseek-search-api`，仅保留 `fetchProvider: http`（`web_fetch` 抓取默认值与行为完全未变）；`dsh-base` 仍同时挂载 `@deepseek-ai/dsh-web-search-deepseek`（`id: 'deepseek-official'`，`apiKeyEnv: DEEPSEEK_API_KEY`）与 `@deepseek-ai/dsh-web-deepseek-api`（`id: 'deepseek-search-api'`）。
  - **Seam 契约与路由常量（`@deepseek-ai/dsh-web`）**：
    - `WebSearchRequest`（`packages/web/web/src/types.ts` 及 `api-catalog.ts`）新增可选字段 `readonly llmProvider?: string`。
    - `packages/web/web/src/index.ts` 新增常量 `DEEPSEEK_MODEL_ROUTES = new Set(['deepseek-official', 'deepseek-account'])`、`DEEPSEEK_ROUTE_SEARCH_PROVIDER = 'deepseek-official'` 与 `OTHER_ROUTE_SEARCH_PROVIDER = 'deepseek-search-api'`。
    - `WebRuntime.search(request, signal)` 与 `WebRuntime.searchReady(llmProvider)` 均将 `llmProvider` 传入 `selectSearchProvider(llmProvider)`，使模型步骤工具准入（`when: ({ modelSelection }) => ctx.web.searchReady(modelSelection.provider)`）与 `applyWebSearchTool` 执行期（读取 `exec.agent?.session.requestContext()?.provider`）严格指向同一个提供方。
  - **服务端搜索实际调用链路**：即使命中 `'deepseek-official'`，DSH 并非在主对话模型请求内直接开启服务端搜索，而是由主模型调用 Harness `web_search` 工具，`runSearchQueries()` 将 `1..searchMaxQueries` 个去重查询并发扇出给 `DeepSeekSearchProvider`，每个查询独立发起一次辅助 `POST ${baseURL}/messages` 请求（默认 `model: 'deepseek-v4-flash'`、`max_tokens: 4096`、`thinking: { type: 'disabled' }`、`tools: [{ type: 'web_search_20250305', name: 'web_search', max_uses: 5 }]`），并在会话日志写入 `web/deepseek-search-llm-request` 事件。
- **选择期顺延条件与执行期零回退规则（`packages/web/web/src/index.ts`、`packages/web/web/tests/web.spec.ts`）**：
  - **显式固定提供方（设置了 `web.searchProvider` 或环境变量 `$DSH_WEB_SEARCH_PROVIDER`）**：在**所有**模型路由上强制生效，完全跳过路由偏好；未注册抛 `WEB_PROVIDER_CONFIGURED_MISSING`，已注册但本地 `available() === false` 抛 `WEB_PROVIDER_CONFIGURED_UNAVAILABLE`，零回退。
  - **未配置提供方（`Automatic` / `自动选择`）时的本地 `available()` 解析**：先以不发起网络请求的同步本地检查 `provider.available()` 过滤出 `usable` 列表。若当前路由对应的 `preferredId` 在 `usable` 中则直接返回；仅当 `preferredId` 未注册或本地 `available() === false`，且剩余可用提供方 `usable.length === 1` 时才顺延选用该唯一可用项；若 `usable.length === 0` 抛 `WEB_PROVIDER_UNAVAILABLE`，若 `usable.length > 1`（例如未挂载 `deepseek-official` 但同时存在可用的 `deepseek-search-api` 与第三方搜索插件）则抛 `WEB_PROVIDER_AMBIGUOUS`。注意在随附 `dsh-base` 中，`DeepSeekSearchProvider.available()` 仅检查凭据解析回调、合法 URL 与正整数上限（本地恒为可用，缺密钥由 `ready()` 撤下工具或在调用时报错）。
  - **执行期绝不回退**：一旦 `resolveProvider()` 选定提供方，执行过程中的凭据缺失（`WEB_PROVIDER_CREDENTIAL_MISSING`）、取消（`WEB_ABORTED`）、HTTP `401`/`403`/`404`/`429`/`5xx`、重定向拒绝或无 `web_search_tool_result` 块均直接抛出 `WebError`（`WEB_PROVIDER_ERROR`），**绝不会**静默改调另一搜索提供方（避免未经提示将查询与凭据发往非预期端点或改变计费方式）。
- **设置界面「自动选择」、8 语种更名与内联摘要提取（`packages/client/ui-settings-web-search/src/client/{WebSearchCard.tsx,locales.ts}`、`packages/web/web-search-deepseek/src/{provider,types}.ts`）**：
  - **设置页卡片（`WebSearchCard.tsx` 与 `locales.ts`）**：因 `dsh-base` 不再预设 `searchProvider`，**网页搜索提供方**下拉框首项及默认选中项变为 **自动选择**（`Automatic`，`AUTO_ID = ''`），其后依次为 **DeepSeek Search API** 与 **DeepSeek 服务端搜索**（`en`/`zh`/`ja`/`es`/`fr`/`de`/`ru`/`pt` 全 8 语种将 `providerLegacy` 由 `DeepSeek (legacy)` / `DeepSeek（旧版）` 更名）。处于搜索自动选择（`search.auto && search.selected === AUTO_ID`）时，页面渲染 `searchAutoHint` 说明与搜索指南链接，隐藏具体提供方的配置面板。已知界面边界：自动选择仅读取组合层，不显示宿主 `$DSH_WEB_SEARCH_PROVIDER` 环境变量覆盖；`searchAutoHint` 为假设两个官方搜索提供方均已注册的固定文案。
  - **内联 `snippet` 提取与说明更新（`web-search-deepseek`）**：`WebSearchResultItem` 新增 `snippet?: string | null`，`mapAnthropicResponse()` 改为 `item.snippet != null && item.snippet.length > 0 ? item.snippet : snippets.get(item.url)`；8 语种 `DeepSeekSearchProvider.description` 更新为「`搜索不按次收费，每次搜索都会额外消耗模型 token。需要 DeepSeek 账号或 API Key。`」，`searchEndpointError()` 错误恢复指引同步改为 `select DeepSeek server-side search under Search`。

## 计费说明边界与未核验限制

- **严禁泛化为「搜索免费」**：
  - 在 `deepseek-official` / `deepseek-account` 路由自动选中或手动固定 `deepseek-official` 时，官方声明与提供方说明仅表示免除**按次搜索 API 调用费**，但每次查询均发起一轮按模型 token 计费的辅助 Messages 请求（默认 `deepseek-v4-flash`），且返回的搜索摘要进入主对话同样消耗主模型输入 token。
  - 在非 DeepSeek 路由（含通过 `llm-pi-ai` 自定义路由调用的 DeepSeek 模型）、无模型请求上下文调用，或手动选择 `deepseek-search-api` 时，搜索请求发往 `/v1/tools/search`，按 `web-deepseek-api.searchBilling`（`auto` / `account` / `api-key`）产生按次 Search API 费用。
- **官方计费声明 ≠ 源码可证明实际账单**：源码仅能证实客户端端点路由、请求体构造与界面说明文案；真实费率、按次费豁免与账户扣费完全由远端 DeepSeek 服务端或网关决定，本报告**未执行线上运行与真实账单核验**。

## 破坏性变化与迁移兼容

- **未配置搜索的 DeepSeek 路由默认切换与自定义网关断点（`docs/upgrade-guide/v0.2.2-rc.4/web-search-deepseek-model-default/guide.{md,zh.md}`）**：
  - 新增 `1` 条升级指南（按前序标签惯例归入 `docs/upgrade-guide/v0.2.2-rc.4/`）。
  - 未配置 `web.searchProvider` 的 `deepseek-official` / `deepseek-account` 会话搜索由 `deepseek-search-api`（`/v1/tools/search`，不写 `web/deepseek-search-llm-request`）切换为 `deepseek-official`（`/anthropic/v1/messages`，写入 `web/deepseek-search-llm-request`）。
  - **自定义网关不兼容场景**：`deepseek-search-api` 默认取对话路由 `baseURL` 的 `<origin>/v1/tools`，而 `web-search-deepseek` 端点不跟随聊天模型 `baseURL`，固定按 `web-search-deepseek.baseURL` → `$DEEPSEEK_SEARCH_BASE_URL` → `https://api.deepseek.com/anthropic/v1` 解析，并在非账号会话中发送 `web-search-deepseek.apiKeyEnv`（默认 `DEEPSEEK_API_KEY`）。若部署将 `deepseek-official` 模型路由指向自定义网关但未配置 `web-search-deepseek.baseURL` / `$DEEPSEEK_SEARCH_BASE_URL`，搜索会把网关密钥发往官方端点导致失败，需在「DeepSeek 服务端搜索」中保存网关 Anthropic 兼容 Base URL，或固定选用 `searchProvider: deepseek-search-api`。
- **向后兼容性**：已存储的 `web.searchProvider` 设置、部署 `cordis.patch.yml` 覆盖项、`$DSH_WEB_SEARCH_PROVIDER`、`fetchProvider: http` 以及 Session v4 JSONL 持久化格式均无缝兼容（细节变化：因 `dsh-base` 不再预设 `deepseek-search-api`，在设置页手动选择 **DeepSeek Search API** 保存时现会显式写入 `searchProvider: deepseek-search-api`，而选择 **自动选择** 保存会清除 `searchProvider`）。
