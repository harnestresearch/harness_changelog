## 概述

`dsh-v0.2.2-rc.4` 是承接 `dsh-v0.2.2-rc.3` 的定向修复 **预发布候选版本（Prerelease）**，共包含 `8` 个提交、改动 `395` 个文件（`+579 / -429` 行，其中非 `package.json` 的源码/文档/升级指南/测试/快照文件仅 `15` 个、`+199 / -49` 行，其余 `380` 个为仅更新版本号的工作区 `package.json` 清单）。源码 diff 将官方 Release 的两条简短说明还原为精确机制：一是将 DeepSeek Messages 流式 `stop_reason: "refusal"` 内容安全拒答从原先中途抛 `MALFORMED_RESPONSE` 改为先产出已计费 `usage` 再抛出不可重试的 `CONTENT_REFUSED`（并登记 `1` 条面向错误码消费方的升级指南）；二是在 `@deepseek-ai/dsh-experimental-liveshare` 启动 owner-gateway 隧道子进程时透传宿主的 `ELECTRON_RUN_AS_NODE`，修复 Electron 桌面端（`mac` / `win`）子进程因误入 GUI 模式被单实例锁秒退导致无法创建分享的问题；此外包含 `1` 项官方说明未提及的 LiveShare 凭据时间窗口测试修复。

## 问题修复与行为变更

- **DeepSeek 流式内容安全拒答（`stop_reason: "refusal"`）结算与 `CONTENT_REFUSED` 错误码（`packages/llm/llm/src/error.ts`、`packages/llm/llm-deepseek/src/translate.ts`，PR #8584 / `74b0e1d9081`）**：
  - **错误码注册与重试策略隔离（`@deepseek-ai/dsh-llm`）**：在 `LLM_FAILURE_CODES`（`BuiltinLlmFailureCode`）中新增 `CONTENT_REFUSED: {}`。与标记了 `{ retryChoice: true }` 的 `MALFORMED_RESPONSE` 不同，`CONTENT_REFUSED` 不进入 `DEFAULT_RETRYABLE_CODES`（`EMPTY_RESPONSE`、`RATE_LIMIT`、`SERVER`、`TIMEOUT`、`TRANSPORT`），也不作为 `RETRY_CODE_CHOICES` 暴露给设置页或 `NormalRetryPolicyConfig` 可重试列表。
  - **SSE 转换与计费用量保留（`@deepseek-ai/dsh-llm-deepseek`）**：
    - 旧行为（`0.2.2-rc.3`）：`translate()` 在收到 `message_delta` 的 `delta.stop_reason === 'refusal'` 时直接交由 `stopReason()` 的 `default` 分支立即抛出 `LlmError('DeepSeek Messages stream: unsupported stop reason refusal', 'MALFORMED_RESPONSE')`，既在到达 `message_stop` 前丢弃了本次尝试已计费的 token 用量，也将内容审核拒答误归类为响应报文畸形。
    - 新行为（`0.2.2-rc.4`）：`message_delta` 遇到 `delta.stop_reason === 'refusal'` 时通过 `refusal(delta.stop_details)` 构造 `new LlmError("DeepSeek refused to answer under its content safety review" + (explanation ? ": " + explanation : ""), "CONTENT_REFUSED")`（提取字符串类型的 `stop_details.explanation`，如 `blocked: messages.1.content.0`）并继续执行 `updateUsage(usage, event.usage)`；待收到终止事件时先汇总 `usage.totalTokens` 并 **`yield { type: 'usage', usage }`**，随后再抛出 `refused`。
  - **Web 与持久化会话表现（`packages/llm/llm-deepseek/README.{md,zh.md}`、`snapshots/session/deepseek-content-refusal/`）**：
    - 默认 `normal` 重试策略直接终止当前尝试；Web 客户端撤回已流式渲染的半截回复；持久化 Session 将已流式输出的文本块、计费 `usage` 与 `{ type: 'finish', reason: { kind: 'error', failure: { code: 'CONTENT_REFUSED', message } } }` 保存在模型历史之外的 `assistant/attempt` 事件中，并以 `turn/end { kind: 'error', error: { code: 'CONTENT_REFUSED', message } }` 结束轮次。
  - **PR 中间提交演进与最终净 Diff 核实**：PR #8584 的早期提交 `f250e23202e` 与 `15762ffc037` 曾一度加入请求侧 `safety_check: { level: 'high' }` 开关/默认发送逻辑，但合并前提交 `e68c0334939` 已将其全部撤回；`rc.3 → rc.4` 最终净 diff 中 `config.ts`、`serialize.ts`、`types.ts`、`wire-types.ts` 均为 **零改动**，且 `loader-composition.spec.ts` 显式断言 `expect(server.requests[0]).not.toHaveProperty('safety_check')`。
- **桌面端 LiveShare 隧道工作进程 Electron Node 模式透传（`packages/experimental/liveshare/src/host/tunnel-worker.ts`，PR #8634 / `f0f05ba737a`）**：
  - **根因机制**：默认关闭的可选实验包 `@deepseek-ai/dsh-experimental-liveshare` 在 `gatewayWorkerCommand()`（`tunnel-supervision.ts`）中以 `executable: process.execPath` 启动常驻子进程 `lib/owner-gateway/cli.js`（源码模式下为 `--import tsx/esm ../owner-gateway/cli.ts`）。在 `@deepseek-ai/dsh-desktop`（`mac` 与 `win`）下，Host 自身由设置了 `ELECTRON_RUN_AS_NODE=1` 的 Electron 主程序二进制运行，`process.execPath` 指向 Electron 可执行文件；而 `TunnelWorker.start()` 此前构造子进程 `env` 时仅传入 `NODE_ENV`、`LIVESHARE_TUNNEL_MODE: 'gateway'` 与代理/证书相关的 `workerTransportEnv(process.env)`，遗漏了 `ELECTRON_RUN_AS_NODE`，导致子进程以第二个桌面 GUI 应用启动，在执行任何网关代码或发出 IPC `ready` 前即被 `acquireDesktopSingleInstance()`（`apps/desktop/src/single-instance.ts`）的 `requestSingleInstanceLock()` 拦截并以退出码 `0` 退出，致使 `probeRelayPublish` / `add-share` 无法完成注册且监督器不断按退避计划重启子进程。
  - **修复方式**：新增 `workerNodeModeEnv(source)`，当 `source.ELECTRON_RUN_AS_NODE !== undefined` 时返回 `{ ELECTRON_RUN_AS_NODE: mode }`、否则返回 `{}`，并合入 `TunnelWorker.start()` 的 `spawn(..., { env })`；`packages/experimental/liveshare/tests/tunnel-worker.spec.ts` 补充校验了 `ELECTRON_RUN_AS_NODE='1'` 透传与 `undefined` 时不注入空键两条分支。
- **LiveShare Owner 凭据时间界限单测真实时钟修复（`packages/experimental/liveshare/tests/owner-credential-horizon.host.spec.ts`，PR #8638 / `9176a089533`，修复 #8465）**：
  - 将硬编码的 `START = Date.parse('2026-10-15T00:00:00.000Z')`（`LIVE = START + 30d = 2026-11-14T00:00:00.000Z`，自 `2026-11-14` 起与宿主 `Date.now()` 比较时恒定过期失败）替换为基于实时时钟的 `Date.now() - DAY` 与 `Date.now() + 30 * DAY`。

## 破坏性变化

- **DeepSeek 流式拒答错误码由 `MALFORMED_RESPONSE` 改为 `CONTENT_REFUSED`（`docs/upgrade-guide/v0.2.2-rc.3/deepseek-refusal-code/guide.{md,zh.md}`）**：
  - 新增 `1` 条升级指南（按 DSH 以前序已发布标签命名的惯例归入 `docs/upgrade-guide/v0.2.2-rc.3/` 目录）。
  - 对 LLM 错误终止块或失败轮次 `turn/end` 错误码进行分支判断的代码，在收到 DeepSeek 流式 `stop_reason: "refusal"` 时需改为处理 `CONTENT_REFUSED`（此前为 `MALFORMED_RESPONSE`）。
- **无持久化会话、配置或 CLI 破坏性变化**：Session JSONL 仍为 `version: 4`，既有 `cordis.yml` 组合配置、CLI 参数及桌面端安装可原地直接升级。
