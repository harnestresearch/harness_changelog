## 概述

`dsh-v0.2.2-rc.3` 是承接 `dsh-v0.2.2-rc.2` 的 **预发布候选版本（Prerelease）**，共包含 `6` 个提交、改动 `515` 个文件（`+10,988 / -669` 行，其中非 `package.json` 源码/测试/文档/快照文件 `135` 个，工作区 `package.json` 清单 `380` 个）。本版本新增可选实验性插件包 `@deepseek-ai/dsh-deepseek-chat-import`，支持将 DeepSeek 官网（`chat.deepseek.com`）导出的 `deepseek_data-*.zip` 归档直接导入为可续聊的原生 DSH 会话；在客户端 UI 层新增 `sidebar.session.action` HOC 槽位与可复用的 `workspace.picker` 组件工厂；增强 `@deepseek-ai/dsh-session-log-export` 对缺失/合成附件引用与提前中断流清理的容错能力；修复 `@deepseek-ai/dsh-desktop` Windows NSIS 更新重启状态窗锁定安装目录的问题；并为 Linux CI 接入经 SHA-256 校验的 `bubblewrap` 归档缓存与有界下载机制。

## 核心亮点

- **DeepSeek 官网对话导出导入实验性插件（`@deepseek-ai/dsh-deepseek-chat-import`，PR #8342）**：作为默认关闭的可选实验性 bundle（在 **插件 → 更多 → 实验性插件** 中启用）随 `@deepseek-ai/dsh` 分发，通过仅限 owner 访问的精确路由上传 `deepseek_data-*.zip`，基于 `fflate` 在内存中完成安全校验与两遍流式导入，将最多 `maxSessions`（默认 `1,000`）个最近更新对话写入所选工作区，并在首个轮次注入受保护的空 `system/message` 表面头节点以确保后续 Agent 恢复续聊时不触发日志损坏错误。
- **客户端 UI 扩展接缝（`sidebar.session.action` 与 `workspace.picker`）**：将侧栏「新建会话」行封装进 root 作用域的 `sidebar.session.action` HOC 槽位，并将空白会话页的工作区选择器发布为可跨插件复用的 `workspace.picker` 组件工厂（`-browse` 与 `-native` 目录选择器同步接入第三处 `workspace.picker.directoryFlow` 子槽）。
- **会话日志 ZIP 导出容错与 Windows 更新锁修复**：`/api/session.export` 遇到已删除、无底层字节或无效附件引用时改写 `attachments-missing.txt` 清单而非中断整包下载，并在中止时通过 `Promise.allSettled` 排空所有打开的文件流；Windows 更新重启提示进程改为以 `GetSystemDirectoryW` 为工作目录启动（PR #8385），彻底消除替换安装目录时的目录占用锁。

## 新功能

- **可选实验性插件包 `@deepseek-ai/dsh-deepseek-chat-import`（`packages/experimental/deepseek-chat-import`，`b8c33a15042` / PR #8342）**：
  - **Bundle 与目录注册**：加入 `OPTIONAL_BUNDLES`（`packages/util/official-bundles/src/bundles.ts`）、`MORE_BUNDLES` 与 `EXPERIMENTAL_BUNDLES`（`plugin-manager.ts`），在 `EXPERIMENTAL_PACKAGE_NAME_EXCEPTIONS` 登记非前缀包名，提供 `cordis.patch.yml`（`insert: deepseek-chat-import`）、`@deepseek-ai/dsh` 依赖声明、Cordis 服务目录项 `ctx.deepseekChatImport`（`DeepseekChatImportService`，归属 `docs/subsystems/persistence.md`）、中英双语插件详情页 `docs/DETAIL.{md,zh.md}` 及 8 语种显示元数据（`de`、`en`、`es`、`fr`、`ja`、`pt`、`ru`、`zh`）。
  - **仅限 Owner 的上传路由与双通道客户端（`src/protocol.ts`、`src/upload.ts`、`src/client/upload.ts`）**：
    - 在宿主端暴露 `@Remote limits(signal)`（非 owner 调用抛出 `deepseekChatImport/owner-only`）并在 `ctx.connection.fetch` 注册精确路由 `POST /api/deepseek-chat-import/archive?workspaceId=…`（`application/octet-stream`），由单并发槽（`busy`）与每请求 `AbortController` 保护（卸载插件时会中止正在运行的导入并等待写入停止后才完成卸载）。
    - 浏览器端在常规 HTTP 服务页使用 `XMLHttpRequest` 上传以汇报字节上传百分比；当宿主运行在无 HTTP 服务器的独立执行上下文（如静态预览壳）时自动切至预启动 `__DSH_TRANSPORT__.fetch` 传输载体。响应采用 `application/x-ndjson` 流式返回 `{ type: 'progress', done, total }` 与单条 `{ type: 'outcome', outcome }`，客户端对每行执行严格联合类型守卫校验，遇到首个非法 JSON 行即刻中止余下流并锁定失败结果。
  - **有界内存归档校验与两遍流式导入器（`src/archive.ts`、`src/format.ts`、`src/conversation.ts`、`src/importer.ts`）**：
    - 可配置上限：`maxSessions = 1000`、`maxUploadBytes = 536_870_912`（`512 MiB`）、`maxEntryBytes = 268_435_456`（`256 MiB`）、`maxTitleBytes = 80`，全程在内存中处理而不落盘暂存。
    - 校验 `manifest.json`（要求 `export_format_version: 3`，面向 `2026-11-12` 导出结构并向后兼容缺失新增可选字段的旧 v3 归档）与 `chat_session_index.json`（缺失报错 `missing-index`）；在打开中央目录时拒绝同名重复条目，对 `ZIP_STORED` 条目强制校验压缩大小与声明大小一致，并在解压前拦截超过 `maxEntryBytes` 的条目。封闭失败原因联合类型为 `'too-large' | 'unreadable-archive' | 'missing-manifest' | 'missing-index' | 'unsupported-version' | 'no-conversations' | 'workspace-not-found' | 'busy'`。
    - 依据 `chat_session_index.json` 的 `updated_at`（平局依次按 `inserted_at`、`id`）选取最新 `maxSessions` 个会话；若所选会话解析或校验失败则自动递补索引中更早的会话（`omittedByLimit` 仅统计从未尝试的会话）。第 1 遍流式扫描预先将选中会话引用的图片（`png`、`jpg`、`jpeg`、`webp`、`gif`）存入 `ctx.attachments`；第 2 遍逐个转换会话并在会话间让出事件循环，每次写入前复核目标 Workspace 仍存在，经 `Session.create()` 执行与实时会话一致的种子校验后写入 `sessionPersistence.create()`，调用 `sessionProjectionCache.coldSnapshot()` 刷新侧栏标题与活动时间，再通过 `workspaceRegistry.attachSession()` 挂载至工作区（已持久化但挂载失败的会话计入 `skipped`）。
    - **会话种子构造与片段映射**：首轮开头写入受保护的空 `system/message` 作为表面节点 `0`（不生成模型消息与可见提示卡；后续恢复会话时 Agent 会用真实系统提示词原地替换它，避免在历史末尾追加系统提示词而触发 `SessionPersistenceCorruptionError`）。分支选择优先取 `current_message_id`（缺失/未知时回退至最大消息 ID）；仅当当前打开的 step 已含工具调用时才在 `stage_id` 变化处切分 step（保持无工具调用 step 合并），工具调用后再出现推理或正文时开启新 step；标题经 `normalizeSessionTitle` 归一化并固定为用户标题（不触发自动生成标题）；`THINK` 与 `RESPONSE` 写入 `assistant/message`（`source: 'deepseek-chat-export'`），`SEARCH` 映射为 `web_search`（`FAILED` 转为错误结果、`WIP` 略过），带地址的 `TOOL_OPEN` 映射为 `web_fetch`，`READ_LINK` 映射为 Markdown `[title](url)` 链接行，未存成功的图片与全部非图片文件映射为无底层字节的合成文件卡片（基于 `dsh-brand` 的 `brandString<AttachmentId>`）。连同问题一并丢弃 `CONTENT_FILTER` 内容过滤撤回轮次，忽略 `CONTENT_RISK` / `TIP` / `TOOL_FIND` / `PARTIAL_FILE_READ` / `TOOL_IMAGE_SEARCH` 及无地址全空 `TOOL_OPEN`，其余非 `FINISHED` 或模板回复以 `turn/end { kind: 'error' }`（`DEEPSEEK_EXPORT_*`，含 `DEEPSEEK_EXPORT_UNFINISHED_REPLY`）收尾且不进入模型上下文。
- **客户端 UI 槽位、工作区选择器工厂与图标扩展（`b8c33a15042`）**：

## 问题修复

- **Windows 桌面安装器更新重启状态窗工作目录锁修复（`apps/desktop/installer/restart-status.h`，PR #8385 / `ac904e118e3`）**：
  - `InstallerStartRestartStatus` 通过 `CreateProcessW` 拉起 `rundll32.exe`（`ShowRestartStatus`）时，将 `lpCurrentDirectory` 显式设为 `GetSystemDirectoryW`（`launch->directory.c_str()`），避免状态提示窗继承应用安装目录句柄导致 NSIS 在更新阶段重命名替换安装目录失败；配套更新 `apps/desktop/tests/windows-restart-status.ps1` 验证状态窗存活期间安装根目录可正常 `Move-Item` 替换。
- **会话日志 ZIP 导出缺失附件容错与文件流释放（`packages/session-query/session-log-export/src/archive.ts`，PR #8342 / `b8c33a15042`）**：
  - `sessionLogZipEntries` 新增捕获 `UNREADABLE_ATTACHMENT_CODES`（`ATTACHMENT_NOT_FOUND`、`INVALID_ATTACHMENT_REF`）：对文件流通过新增 `headOf()` 助手在 yield ZIP 条目前预读首块（使 `ATTACHMENT_CORRUPT` 等真实完整性/I/O 错误仍在写入条目前快速失败），将缺失或无效引用逐条记入 `attachments-missing.txt`（`<归档内路径>\t<错误原因>`）并继续导出其余条目。
  - 使用 `openStreams` 集合追踪所有活动文件异步迭代器，在 `finally` 中通过 `Promise.allSettled` 逐一关闭提前取消或未消费完的流，防止文件句柄泄漏且不掩盖飞行中的异常。
- **CI 已校验 Bubblewrap 归档缓存与有界下载（`scripts/ci-verified-download.sh`、`scripts/prepare-ci-bubblewrap.sh`、`.github/workflows/{ci,ci-master,e2e}.yml`，PR #8383 / `bbad94f927a` & `68f83cc9926`）**：
  - 新增 `acquire_verified_archive`，兼容探测 GNU `sha256sum` 与 macOS `shasum -a 256`（工具缺失返回退出码 `2` 而非误判哈希不匹配），采用 `.partial` 临时文件 + `EXIT` trap 清理与原子替换，并为 `curl` 配置严格超时重试边界（`--connect-timeout 15 --max-time 60 --retry 8 --retry-all-errors --retry-max-time 240`）。
  - 在托管 Linux CI 与 E2E 工作流中通过 `actions/cache/{restore,save}@v6.1.0` 缓存 `~/.cache/dsh-ci/bubblewrap`（`bubblewrap_0.12.0-1_amd64.deb`），在持久化自建机群节点上显式跳过 Actions 缓存。
