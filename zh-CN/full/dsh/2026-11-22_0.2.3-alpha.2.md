## Node.js 精确版本范围与检查位置实证

### 声明的 semver 范围真值表（`^24.22.3 || >=26.13.1`）

在 `package.json:9`（`@deepseek-ai/dsh-root`）与 `apps/cli/package.json:191`（`@deepseek-ai/dsh`）中由 `">=24.9.0"` 改为 `"^24.22.3 || >=26.13.1"`。按 npm `node-semver` 规范展开为 `>=24.22.3 <25.0.0-0 || >=26.13.1`：

| Node.js 版本 / 主版本线 | 是否满足 `engines.node` | 等于 / 大于等于语义与 CI 验证覆盖情况 |
|---|---|---|
| `< 24.22.3`（`20.x`、`22.x`、`23.x`、`24.0.0`–`24.22.2`） | **否（排除）** | 不满足 `^24.22.3 \|\| >=26.13.1`（注：独立发布的 `native/system/packages/*/package.json` 仍保持 `">=20"`）。 |
| `24.22.3`（精确版本） | **是（允许）** | 受支持的最低 `24.x` 版本；同时是 `scripts/run-gates.ts:499`（设置 `DSH_NODE_COMPAT_BUILD=1` 时）、`scripts/primary-runtime/prepare.ts:278`（读取 `lock.json` `24.22.3`）以及 Python SDK `pkg --sea` 打包**严格相等 `===`** 检查唯一接受的版本。 |
| `24.22.4`、`24.23.0` 及更高 `24.x`（`< 25.0.0-0`） | **是（允许）** | **`24.x` 内 `>=24.22.3`（非严格等于 `24.22.3`）**；CI 主线采用 `PRIMARY_NODE_VERSION: '^24.22.3'` 覆盖最新 `24.x`。 |
| `25.x`（`25.0.0`–`25.x.y`） | **否（排除）** | 被 `^24.22.3` 隐含的 `<25.0.0-0` 上界与第二分支 `>=26.13.1` 共同排除（上版 `>=24.9.0` 曾从语义上放行 `25.x`；官方升级指南未单独点名 `25.x`）。 |

| `27.0.0` 及以上（`27.x+`、`28.x+`） | **是（semver 允许）** | 第二分支为 `>=26.13.1`（非 `^26.13.1`），**未设主版本上界**；但 **CI 不测试 Node 27+**（实际兼容性超出 `24.x`/`26.x` 未验证）。 |

### 实际检查位置与未做运行时校验的边界

1. **包清单声明（仅安装期元数据，未启用 `engine-strict`）**：
   - 全仓仅 `package.json:8-10` 与 `apps/cli/package.json:190-192` 声明 `"node": "^24.22.3 || >=26.13.1"`。仓库不存在 `.npmrc`，`pnpm-workspace.yaml` 亦未配置 `engineStrict: true`；在 npm/pnpm 默认配置下，不兼容的宿主 Node 版本仅输出警告而不中止安装，除非调用方环境自行开启 `engine-strict=true`。
   - `native/system/packages/{entry,darwin-arm64,darwin-x64,linux-arm64,linux-x64}/package.json` 仍维持 `"node": ">=20"`（`.github/workflows/node-addon-system.yml:132,146,160` 亦保留 Node `20`/`22`/`26` 矩阵）。
2. **CLI 与应用运行时启动链路（无运行时 `engines.node` 门禁）**：
   - `apps/cli/src/bin.ts`、`apps/cli/src/installed-bin.ts` 与 `apps/cli/src/profile-boot.ts` 在启动期**均未校验 `process.versions.node`**（`apps/cli/src/startup-diagnostics.ts:43` 仅在启动失败诊断报告中记录 `nodeVersion: process.version`）。
   - `packages/boot/app-boot/src/plugin-compatibility.ts:56-61` 仅校插件的 `engines.dsh`（及 DSH `peerDependencies`），不校 `engines.node`。
   - `vendor/loader/src/internal.ts:133-134` 仍仅做 `major < 22` 判断，并通过属性探测（`getOrCreateModuleJob` vs `getModuleJobForImport`）区分 v2/v1 ESM 加载器。
   - `packages/boot/app-boot/src/profile-resolution/resolver.ts:906` 与 `packages/boot/hmr/src/package-manifest.ts:114` 仍保留面向 Node `<24.12` 的 v1 适配代码，本版仅更新了 `/* v8 ignore else */` 注释（另同步更新 `packages/ptc-runtime/ptc-runtime-node/src/imports/vm-modules.ts:16` 注释）。
3. **Python SDK 开发态 `node` 载体（仅更新提示文案，未探测 Node 版本）**：
   - `python/sdk-runtime/src/deepseek_harness_runtime/__init__.py:14,147-152`（`_node_launch_args()`）仅检查 `shutil.which("node") is None`，把缺失 `node` 时的报错文案改为 `"the node runtime mode needs a system \`node\` (^24.22.3 || >=26.13.1) on PATH; install Node.js or use the exe mode"`，**并未执行 `node --version` 或拦截旧版系统 Node**。
4. **代码与 CI 中的实际硬检查位置**：
   - **清单契约单测**：`scripts/ci-compatible-selfhosted.spec.ts:62-70` 断言 `package.json` 与 `apps/cli/package.json` 的 `engines.node` 精确等于 `` `^${BUILD_BACKED_NODE_COMPAT_VERSION} || >=26.13.1` ``（即 `^24.22.3 || >=26.13.1`），`88-91` 行断言 CI `node-compat` 矩阵包含 `node: '24.22.3'`（`build: '1'`）与 `node: 26`（`build: ''`）；同步更新 `scripts/ci-workflow.spec.ts:40`、`scripts/preview-workflow.spec.ts:46`、`scripts/publint-all.spec.ts:40`。
   - **CI 构建兼容性门禁（严格相等 `=== '24.22.3'`）**：`scripts/run-gates.ts:113` 将 `BUILD_BACKED_NODE_COMPAT_VERSION` 由 `'24.9'` 改为 `'24.22.3'`，`496-501` 行将原先按前缀 `startsWith('24.9.')` 触发构建改为由环境变量 `DSH_NODE_COMPAT_BUILD=1` 显式开启，并在开启时严格断言 `process.versions.node !== BUILD_BACKED_NODE_COMPAT_VERSION` 即抛错（使恰好运行在 `24.22.3` 上的主线任务在未设 `DSH_NODE_COMPAT_BUILD` 时保持 source-only；配套单测见 `scripts/run-gates.spec.ts:1025-1095`）。
   - **内置主运行时锁文件与冒烟校验（严格相等 `=== '24.22.3'`）**：`scripts/primary-runtime/lock.json:2` 将 `"nodeVersion"` 由 `"24.21.0"` 升至 `"24.22.3"`，并更新全部 5 个目标的 `nodeSha256`（`win-x64` 第 `8` 行、`mac-arm64` 第 `32` 行、`mac-x64` 第 `56` 行、`linux-x64` 第 `80` 行、`linux-arm64` 第 `104` 行；Python 维持 `3.12.14` / `20260901`）；`scripts/primary-runtime/prepare.ts:278` 在准备期冒烟中校验 `process.versions.node !== manifest.node`。
   - **Python SDK 单文件可执行构建器**：`scripts/build-exe-for-python-sdk.ts:33-35,112-114,127-129,412-417` 引入 `NODE_VERSION = primaryLock.nodeVersion`（`24.22.3`），将 `--targets` 参数校验由 `/^node\d+$/` 收紧为字面量 `nodeRange === 'node24'`（拒绝 `node24.20.0` 等，见 `scripts/build-exe-for-python-sdk.spec.ts:180,187-198`），并将传给 `pkg --sea` 的目标由浮动 `node24-<platform>-<arch>` 改为精确 `node24.22.3-<platform>-<arch>`。
