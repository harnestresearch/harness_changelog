## 版本概览

本条目基于官方 macOS `arm64` 双安装包（[0.5.12](2026-11-14_0.5.12.md) → `0.5.13`）的只读静态解包比对；仅核验官方 macOS `arm64` 产物，未逆向 Windows 或 Linux 安装包，亦未运行任何被测程序。本地静态证据表明：`0.5.13` 在渲染层重做了 `ApplicationTransport.subscribe` 达到 `64` 订阅上限时的处理（等待 `releaseRequested` 在途释放并复检、辅以 30 秒节流诊断日志，而非取消 `64` 上限），在 `qoder-worker-runtime.obf.mjs` 解码字符串表中新增 6 条涉及审批评估边界、Bash 风险自评与本地 Auto 门控/黑名单/策略版本说明的字符串（`14,169 → 14,175`），将 Agent SDK 推进 12 个 alpha 版本（`1.0.60-alpha.50` → `1.0.60-alpha.62`）并将 `qodercli` 升至 `1.1.86-hotfix.5.2`，同时重编译打包 `qoder-office-xlsx`。

## 静态可证改动明细

- **渲染层 `ApplicationTransport.subscribe` 达上限等待释放与 30 秒限频日志（`Dta6yTTQ.js` → `BHeyMntc.js`）**
  - 渲染层传输模块 `app/out/renderer/assets/Dta6yTTQ.js`（`176,239` B）替换为 `BHeyMntc.js`（`177,975` B，`+1,736` B；全渲染层共 `37` 个哈希轮换 JS chunk 合计 `+3,013` B、CSS 零变化，含主入口 chunk `CAGvh22m.js` → `DB5RheoM.js` `+1,277` B）：
    - 单连接并发订阅上限仍为 **`64`**（两版均为 `this.subscriptions.size >= 64`，**并未取消或调高该上限**）。
    - 当 `this.subscriptions.size >= 64` 时，行为由 `0.5.12` 的立即抛出 `APPLICATION_RATE_LIMITED` 改为：先筛选当前订阅表中标记 `releaseRequested` 的在途释放项，调用 `this.waitForReleases(Promise.all(n.map(([id, sub]) => this.releaseSubscription(id, sub))), signal)` 等待释放完成，再重新检查 `this.subscriptions.size >= 64`（及取消/关闭状态），仍满额时才抛出 `APPLICATION_RATE_LIMITED`。
    - 新增 `lastLimitLogAt`（`30,000` ms 即 30 秒节流）与 `logSubscriptionLimit(requestedMethod)`，输出 `category: "ApplicationTransport"` 的 `warn` 日志 `"Application subscription limit reached"`，统计各 method 的 `{ active, establishing, releasing, releaseFailed, oldestAgeMs }`（订阅表项同步新增 `method`、`startedAt` 与 `releaseRequested` 字段）。
    - 全部 `37` 个变更渲染层 chunk 中新增的英文明文字面量仅为 `"Application subscription limit reached"`、`"ApplicationTransport"` 及订阅状态词（`"establishing"`、`"releasing"`、`"releaseFailed"`），**无新增面向用户的 UI 文案**。
  - **证据边界说明**：代码层面的“达 64 上限时等待在途释放再复检”在机制上与官方说明“频繁切任务或通知积压后任务打不开”吻合，但将其归因为具体用户故障修复属于**静态行为推断**，未经实机运行验证。
